# Textarea

# The Textarea: A Senior Engineer's Complete Breakdown
The multi-line text input that handles long-form content entry. Here's everything from first principles to production code.

This doc follows the Private ([https://app.clickup.com/8495850/docs/838qa-81211/838qa-200531](https://app.clickup.com/8495850/docs/838qa-81211/838qa-200531)) and its visual styles are drawn from the Private ([https://app.clickup.com/8495850/docs/838qa-87871/838qa-200551](https://app.clickup.com/8495850/docs/838qa-87871/838qa-200551)).

* * *
## 1\. What a Textarea Actually Is
A **textarea** is a multi-line, free-form text input for longer content: comments, descriptions, messages, code, notes. It's the `<textarea>` element — distinct from `<input type="text">` which is single-line.

**Textarea (this doc):** multi-line text entry with vertical resize, scroll, and optional character count.
**Input/Field:** single-line text. Different component, different use.
**Rich Text Editor:** a textarea with formatting (bold, links, etc.). A superset, not this doc.

* * *
## 2\. Why It Matters
**Every form with comments, descriptions, or messages uses one.** Feedback forms, support tickets, social posts, bio fields, code inputs. It's one of the most common form elements.
**Auto-resize is the UX differentiator.** A fixed-height textarea with scroll is functional; one that grows with content is delightful. Users see their full message without scrolling inside a tiny box.
**Character limits are trust signals.** Showing "42/280" tells users they're within bounds. Hiding the limit until they hit it feels like a trap.

* * *
## 3\. Anatomy
**Label:** describes what to type. Required for accessibility.
**Container/Border:** the visible boundary. Changes on focus/error.
**Text area:** the editable multi-line content region.
**Placeholder (optional):** ghost text showing expected content. Disappears on focus/type.
**Character count (optional):** "42/280" display, often bottom-right.
**Helper text (optional):** guidance below the field.
**Error message (optional):** validation feedback, replaces helper text.
**Resize handle (optional):** browser-native or custom drag-to-resize.

* * *
## 4\. Sizes / Scale

| Token | Min Height | Rows | Font | Use |
| ---| ---| ---| ---| --- |
| S | 80px | 3 | 13px | Short comments, labels |
| M | 120px | 5 | 14px | Default (descriptions, messages) |
| L | 160px | 7 | 14px | Long-form (articles, bios) |
| XL | 240px | 10+ | 14px | Code blocks, templates |

Width is always 100% of parent container. Auto-resize overrides min-height dynamically.

* * *
## 5\. States
**Empty:** placeholder visible, no content.
**Filled:** content present, placeholder hidden.
**Focus:** border highlights (brand color), ready for input.
**Disabled:** grayed out, not editable, not focusable.
**Read-only:** content visible and selectable, but not editable. Still focusable.
**Error:** red border + error message below. Character count may turn red if over limit.
**Over-limit:** character count exceeds max, visual warning (red count, may prevent further typing or allow with warning).
**Auto-resizing:** height grows as content is added, shrinks as content is removed.

* * *
## 6\. Types / Variants
**Fixed height:** traditional. Set rows/height, scroll internally.
**Auto-resize:** grows with content. No internal scroll until a max-height.
**With character count:** shows current/max characters.
**With toolbar:** mini formatting bar above (bold, italic, link). Bridges textarea and rich editor.
**Code textarea:** monospace font, tab-indent support, optional line numbers.
**Borderless/Ghost:** no visible border until hover/focus (for inline editing).

* * *
## 7\. When to Use (and When Not To)
**Use a textarea when:**
*   Input will be more than one line (comments, descriptions, messages)
*   Users need to see context of what they've typed
*   Free-form text without formatting requirements

**Use something else when:**
*   Single-line input (name, email) → Input field
*   Rich formatting needed (bold, lists, images) → Rich text editor
*   Structured data (date, number) → Specialized input
*   Very short text (< 50 chars typical) → Input field

* * *
## 8\. Across Design Systems
**Material:** `TextField` with `multiline` and `rows` props. Uses outlined or filled variants.
**Apple HIG:** `UITextView` / `TextEditor` in SwiftUI. No built-in character count.
**Fluent:** `Textarea` with resize options and character count built in.
**Ant Design:** `<Input.TextArea>` with `showCount`, `maxLength`, `autoSize` props.
**shadcn:** `<Textarea>` — minimal styled wrapper around native `<textarea>`.
**Chakra:** `<Textarea>` with size, resize, and focus-border-color props.

### 9.3 React + TypeScript (auto-resize)

```typescript
import { forwardRef, TextareaHTMLAttributes, useRef, useCallback, useEffect } from "react";

interface TextareaProps extends TextareaHTMLAttributes<HTMLTextAreaElement> {
  autoResize?: boolean;
  maxLength?: number;
  showCount?: boolean;
  error?: string;
  label: string;
}

export const Textarea = forwardRef<HTMLTextAreaElement, TextareaProps>(function Textarea(
  { autoResize, maxLength, showCount, error, label, className = "", ...rest }, ref
) {
  const internalRef = useRef<HTMLTextAreaElement>(null);
  const textareaRef = (ref as any) || internalRef;

  const resize = useCallback(() => {
    const el = textareaRef.current;
    if (!el || !autoResize) return;
    el.style.height = "auto";
    el.style.height = `${el.scrollHeight}px`;
  }, [autoResize]);

  useEffect(resize, [rest.value, rest.defaultValue]);

  const count = String(rest.value ?? "").length;

  return (
    <div className="field">
      <label>{label}</label>
      <textarea ref={textareaRef} className={`textarea ${error ? "textarea--error" : ""} ${className}`}
                maxLength={maxLength} aria-invalid={!!error} aria-describedby={error ? "err" : undefined}
                onInput={resize} {...rest} />
      <div className="field__footer">
        {error && <span id="err" className="field__error" role="alert">{error}</span>}
        {showCount && maxLength && <span className="field__count" aria-live="polite">{count}/{maxLength}</span>}
      </div>
    </div>
  );
});
```

```typescript
"use client";
import { useState, useEffect } from "react";

export function CharCount({ inputId, max }: { inputId: string; max: number }) {
  const [count, setCount] = useState(0);
  useEffect(() => {
    const el = document.getElementById(inputId) as HTMLTextAreaElement;
    if (!el) return;
    const update = () => setCount(el.value.length);
    el.addEventListener("input", update);
    update();
    return () => el.removeEventListener("input", update);
  }, [inputId]);

  return (
    <span className={`field__count ${count > max * 0.9 ? 'text-amber-400' : ''}`}
          aria-live="polite">{count}/{max}</span>
  );
}
```

### 9.6 shadcn/ui

```typescript
// components/ui/textarea.tsx
import * as React from "react";
import { cn } from "@/lib/utils";

export interface TextareaProps extends React.TextareaHTMLAttributes<HTMLTextAreaElement> {
  error?: string;
  label: string;
  showCount?: boolean;
  autoResize?: boolean;
}

const Textarea = React.forwardRef<HTMLTextAreaElement, TextareaProps>(
  ({ className, error, label, showCount, autoResize, maxLength, ...props }, ref) => {
    const internalRef = React.useRef<HTMLTextAreaElement>(null);
    const textareaRef = (ref as any) || internalRef;
    const [count, setCount] = React.useState(0);

    const handleInput = (e: React.FormEvent<HTMLTextAreaElement>) => {
      setCount(e.currentTarget.value.length);
      if (autoResize) {
        e.currentTarget.style.height = "auto";
        e.currentTarget.style.height = `${e.currentTarget.scrollHeight}px`;
      }
      props.onInput?.(e);
    };

    return (
      <div className="space-y-1.5">
        <label className="text-sm font-medium leading-none">{label}</label>
        <textarea
          ref={textareaRef}
          className={cn(
            "flex min-h-[80px] w-full rounded-md border border-input bg-background px-3 py-2 text-sm ring-offset-background placeholder:text-muted-foreground focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 disabled:cursor-not-allowed disabled:opacity-50",
            error && "border-destructive focus-visible:ring-destructive",
            autoResize && "resize-none overflow-hidden",
            className
          )}
          maxLength={maxLength}
          aria-invalid={!!error}
          aria-describedby={error ? "textarea-error" : undefined}
          onInput={handleInput}
          {...props}
        />
        <div className="flex justify-between">
          {error && <p id="textarea-error" className="text-sm text-destructive" role="alert">{error}</p>}
          {showCount && maxLength && (
            <span className="text-xs text-muted-foreground ml-auto tabular-nums" aria-live="polite">
              {count}/{maxLength}
            </span>
          )}
        </div>
      </div>
    );
  }
);
Textarea.displayName = "Textarea";
export { Textarea };
```

```typescript
import { Component, Input, forwardRef } from '@angular/core';
import { CommonModule } from '@angular/common';
import { ControlValueAccessor, NG_VALUE_ACCESSOR, ReactiveFormsModule } from '@angular/forms';

@Component({
  selector: 'app-textarea',
  standalone: true,
  imports: [CommonModule, ReactiveFormsModule],
  providers: [{ provide: NG_VALUE_ACCESSOR, useExisting: forwardRef(() => TextareaComponent), multi: true }],
  template: `
    <div class="field">
      <label [for]="id">{{ label }}</label>
      <textarea [id]="id" [class]="'textarea' + (error ? ' textarea--error' : '')"
                [placeholder]="placeholder" [maxlength]="maxlength" [rows]="rows"
                [disabled]="isDisabled"
                [attr.aria-invalid]="error ? true : null"
                [attr.aria-describedby]="error ? id + '-err' : showCount ? id + '-count' : null"
                (input)="onInput($event)" (blur)="onTouched()">{{ value }}</textarea>
      <div class="field__footer">
        <span *ngIf="error" [id]="id + '-err'" class="field__error" role="alert">{{ error }}</span>
        <span *ngIf="showCount && maxlength" [id]="id + '-count'" class="field__count" aria-live="polite">
          {{ value.length }}/{{ maxlength }}
        </span>
      </div>
    </div>
  `,
  styleUrls: ['./textarea.component.css']
})
export class TextareaComponent implements ControlValueAccessor {
  @Input() label = 'Message';
  @Input() placeholder = '';
  @Input() maxlength?: number;
  @Input() showCount = false;
  @Input() autoResize = false;
  @Input() error?: string;
  @Input() rows = 5;
  @Input() id = 'textarea-' + Math.random().toString(36).slice(2, 8);

  value = '';
  isDisabled = false;
  private onChange: (v: string) => void = () => {};
  onTouched: () => void = () => {};

  writeValue(val: string) { this.value = val || ''; }
  registerOnChange(fn: any) { this.onChange = fn; }
  registerOnTouched(fn: any) { this.onTouched = fn; }
  setDisabledState(disabled: boolean) { this.isDisabled = disabled; }

  onInput(e: Event) {
    const target = e.target as HTMLTextAreaElement;
    this.value = target.value;
    this.onChange(this.value);
    if (this.autoResize) {
      target.style.height = 'auto';
      target.style.height = `${target.scrollHeight}px`;
    }
  }
}
```

```typescript
class UiTextarea extends HTMLElement {
  static observedAttributes = ['label', 'placeholder', 'maxlength', 'rows', 'error', 'auto-resize', 'show-count', 'disabled'];

    const rows = this.getAttribute('rows') || '5';

        textarea.error { border-color: #b42318; }
        textarea:disabled { opacity: 0.5; cursor: not-allowed; resize: none; }
        .footer { display: flex; justify-content: space-between; font-size: 12px; color: #888; }
        .error-msg { color: #ef4444; }
      </style>
      <div class="field">
        <label for="ta">${label}</label>
        <textarea id="ta" placeholder="${placeholder}" rows="${rows}"
                  ${maxlength ? `maxlength="${maxlength}"` : ''} ${disabled ? 'disabled' : ''}
                  ${error ? 'aria-invalid="true" aria-describedby="err"' : ''}
                  class="${error ? 'error' : ''}"></textarea>
        <div class="footer">
          ${error ? `<span id="err" class="error-msg" role="alert">${error}</span>` : '<span></span>'}
          ${showCount && maxlength ? `<span class="count" aria-live="polite">0/${maxlength}</span>` : ''}
        </div>
      </div>`;
  }

  bindEvents() {
    const ta = this.shadowRoot!.querySelector('textarea')!;
    const countEl = this.shadowRoot!.querySelector('.count');

      if (this.hasAttribute('auto-resize')) {
        ta.style.height = 'auto';
        ta.style.height = `${ta.scrollHeight}px`;
      }
      this.dispatchEvent(new CustomEvent('input', { detail: { value: ta.value } }));
    });
  }
}
```

```swift
                        .stroke(error != nil ? Color.red : Color.gray.opacity(0.3), lineWidth: 1.5)
                )
                .onChange(of: text) { newValue in
                    if let max = maxLength, newValue.count > max {
                        text = String(newValue.prefix(max))
                    }
                }
                .accessibilityLabel(label)

            // Placeholder overlay (TextEditor doesn't have native placeholder)
            .overlay(alignment: .topLeading) {
                if text.isEmpty {
                    Text(placeholder)
                        .foregroundColor(.gray)
                        .padding(.horizontal, 16)
                        .padding(.vertical, 20)
                        .allowsHitTesting(false)
                }
            }

            HStack {
                if let error = error {
                    Text(error)
                        .font(.caption)
                        .foregroundColor(.red)
                        .accessibilityLabel("Error: \(error)")
                }
                Spacer()
                if let max = maxLength {
                    Text("\(text.count)/\(max)")
                        .font(.caption)
                        .foregroundColor(text.count > Int(Double(max) * 0.9) ? .orange : .gray)
                }
            }
        }
    }
}

// @State private var feedback = ""
// TextareaField(text: $feedback, label: "Feedback", placeholder: "Share your thoughts...", maxLength: 2000)
```

## 10\. Accessibility
**Label is mandatory.** Every textarea must have a visible `<label>` associated via `for`/`id`. Placeholder is NOT a label (it disappears on focus, leaving the user without context).

**`aria-describedby`** links the textarea to its helper text, character count, and/or error message. Multiple IDs space-separated.

**`aria-invalid="true"`** set dynamically when validation fails. Pair with an error message that has `role="alert"` so it's announced immediately on injection.

**Character count uses** **`aria-live="polite"`** so screen readers announce the count without interrupting. Debounce the update (every ~10 characters or on pause) to avoid spamming announcements on every keystroke.

**Resize handle:** the native browser resize grip is keyboard-accessible in some browsers but not all. If resize is critical to the UX, consider adding an explicit resize affordance (a button that toggles between height presets) for keyboard users.

**Read-only vs disabled:** `readonly` keeps the textarea focusable and its content selectable/copyable. `disabled` removes it from the tab order entirely. Choose deliberately: content users need to copy should be `readonly`, not `disabled`.

**Focus visible:** the textarea shows a clear `:focus-visible` ring on keyboard focus. Never `outline: none` without a replacement.

**Contrast:** text vs. background ≥ 4.5:1; border vs. background ≥ 3:1 (non-text element). Error state border must also pass.

## 10\. Accessibility
**Label is mandatory.** Every textarea needs a visible `<label>` linked via `for`/`id`. Placeholder is NOT a label (it disappears on focus, fails contrast, and isn't reliably announced). No label = no accessible name = unusable for screen-reader users.

**`aria-describedby`** links the textarea to its helper text, character count, and/or error message. Multiple IDs are space-separated: `aria-describedby="help count"`.

**`aria-invalid="true"`** when the field is in an error state. Pair with `aria-describedby` pointing at the error message so the user hears _what's wrong_, not just "invalid."

**Error messages use** **`role="alert"`** (or are injected into a live region) so they're announced immediately when they appear, not just painted.

**Character count uses** **`aria-live="polite"`** so it announces without interrupting. Debounce the announcement (don't announce every keystroke; announce on pause or every ~10 characters) to avoid spamming AT users.

**Keyboard:** a native `<textarea>` is fully keyboard-operable by default (Tab to focus, type to enter, Shift+Enter or Enter for newline). Don't override Enter for "submit" without a clear escape — that traps users who want a line break.

**Resize:** the native drag-to-resize handle is somewhat accessible in some browsers but not reliably. If resize is critical, provide an explicit button ("Expand field") for keyboard users.

**Contrast:** text vs. background ≥ 4.5:1; border vs. background ≥ 3:1 (non-text element). The placeholder color specifically must clear 4.5:1 too (most default placeholders fail this).

**Focus visible:** a clear `:focus-visible` ring on the textarea border. Never `outline: none` without a replacement.

**Read-only vs. disabled:** `readonly` keeps the field focusable and selectable (users can copy); `disabled` removes it from tab order entirely. Choose deliberately based on whether users need to read/copy the content.

## 11\. Innovative / Emerging Ideas
*   **`field-sizing: content`**\*\*\*\***:** CSS native auto-resize (Chrome 123+). No JS needed. The future.
*   **AI autocomplete:** ghost-text suggestions that complete on Tab (GitHub Copilot style)
*   **Collaborative editing:** real-time multi-cursor (Google Docs in a textarea)
*   **Voice-to-text input:** speech recognition feeding into textarea
*   **Smart paste:** pasting rich content auto-strips formatting for plain-text fields

* * *
## 12\. Conversion / UX Killers
*   **Fixed tiny height (2 rows) for long content:** users type into a letterbox. Auto-resize or minimum 5 rows.
*   **No character count with a limit:** users compose a 2000-char message, submit, get truncated or rejected.
*   **Placeholder as label:** placeholder disappears on focus, user forgets what to type.
*   **No error recovery:** textarea content lost on failed submit. Persist in state.
*   **Scroll-within-scroll:** a short textarea inside a scrollable container creates nested scroll hell on mobile.

* * *
## 13\. Advanced Patterns
**Mention/tag support (@user):** textarea with autocomplete triggered by special characters. Popover list on `@`, inserts a tagged token.

**Markdown preview:** split pane or toggle between raw textarea and rendered preview.

**Tab support for code:** override Tab key to insert `\t` instead of moving focus (with an escape hatch — Esc then Tab to leave).

* * *
## 14\. Performance & Bundle Cost
*   **Auto-resize with scrollHeight** triggers layout recalculation on every keystroke. Throttle with `requestAnimationFrame` or use `field-sizing: content` (CSS-only, zero JS cost).
*   **Character count re-render:** don't re-render the entire form on every keystroke. Isolate the count in its own state/component.
*   **Large content:** textareas with 10,000+ characters can lag. Consider virtual rendering or debounced state updates.

* * *
## 15\. Security
*   **Server-side length validation.** `maxlength` is client-only. Always validate on the server.
*   **XSS on render:** when displaying textarea content back to users, escape HTML. `<script>` in a comment field is the classic XSS vector.
*   **Rate limiting:** textareas in public forms (comments, reviews) need server-side rate limiting and spam detection.

* * *
## 16\. Senior-Level Checklist
*   Paired with visible `<label>`
*   `aria-describedby` links to helper/count/error
*   `aria-invalid` set on error
*   Auto-resize works (CSS `field-sizing` or JS fallback)
*   Character count announces politely (debounced `aria-live`)
*   Error message has `role="alert"` when dynamically injected
*   Content survives failed form submission (no data loss)
*   `maxlength` enforced server-side too
*   Output is HTML-escaped before display
