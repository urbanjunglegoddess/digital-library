# Phone Input

# Phone Input

A specialized text field for entering a telephone number, paired with a country selector that carries the dial code (e.g. `+1`, `+44`, `+234`) and drives per-country formatting and validation. It is the single most locale-sensitive input in most sign-up and checkout flows: get it wrong and you silently lock out entire countries.
* * *

## 1\. What It Actually Is

A Phone Input is a composite control: a `<input type="tel">` for the number, plus an adjacent **country-code combobox** (a listbox of countries, each shown as flag + country name + dial code) that determines which country the digits belong to. As the user types, an as-you-type formatter groups the digits the way that country writes them, while the value stored and sent to the server is the **E.164** canonical form (`+`, country code, national number, no spaces or punctuation, max 15 digits).

The three things people constantly confuse it with, named and distinguished:

*   **A plain text input with a regex** — `type="text"` with `pattern="[0-9-]+"`. This has no country context, no dial code, and almost always hardcodes a US 10-digit assumption that rejects valid numbers everywhere else. A real Phone Input is country-aware.
*   **A Number Input (****`type="number"`** **/ spinbutton)** — numbers with steppers, `aria-valuenow`, arrow-key increment. A phone number is _not_ a numeric quantity: leading zeros matter, `+` matters, and you never want a scroll wheel changing someone's phone number. Never use `type="number"` for phone.
*   **A masked input (credit card, SSN)** — a fixed-length format mask. Phone masks are _variable_: they change the instant the country changes, and many countries have multiple valid lengths. A phone field is a mask that is chosen at runtime from the selected country, not a static template.

**Rule of thumb:** if the value is a callable/textable telephone number that needs a country and a dial code, it is a Phone Input. If it is a fixed-format secret or a counted quantity, it is a masked or number input. If you are about to write `maxlength="10"`, stop — you have already broken it for the other 200 countries.
* * *

## 2\. Why It Matters

*   **Conversion and reach (revenue).** A phone field that rejects legitimate international formats is a hard wall at the exact moment of sign-up or checkout. A US-only `\d{10}` regex silently fails every UK, Nigerian, Indian, or German customer. For a global product this is not a bug report — it is churn nobody logs, because the rejected user just leaves.
*   **Deliverability and OTP success (trust + cost).** SMS one-time-passcodes only work if the number is stored in a form the SMS gateway accepts, which is E.164. Store a locally-formatted string like `(404) 555-0132` and your Twilio/Vonage send fails or misroutes, the user never gets the code, and support eats the ticket. Correct normalization is the difference between an OTP that arrives and a locked-out account.
*   **Accessibility (legal + inclusion).** The country selector is a combobox with a flag. Flags are images; a screen reader user hears nothing from a flag alone. If the only label on an option is a flag glyph, the control is unusable non-visually — a WCAG 1.1.1 and 4.1.2 failure. The flag must be decorative and the country name + dial code must be real text.
*   **Fraud and abuse surface (security + spend).** Phone fields feed SMS-sending endpoints, and SMS costs real money per message. An unthrottled "send code" tied to a phone field is an SMS-pumping / toll-fraud target that can run up thousands of dollars, and a naive "this number is already registered" error leaks account existence. The input is the front of a money-spending pipe.
* * *

## 3\. Anatomy

Every well-built Phone Input is composed of these parts:

*   **Field container** — the bordered box that visually unifies the country selector and the number field so they read as one control, with a single shared focus/error treatment.
*   **Country combobox trigger** — the button (or combobox) on the leading edge showing the _currently selected_ country: flag + dial code (e.g. `🇺🇸 +1`) and a chevron. Has `aria-haspopup="listbox"` / `aria-expanded`. The flag is `aria-hidden`; the accessible name is the country name and code as text.
*   **Country listbox panel** — the popup: a scrollable, typeahead-searchable list of countries. Each row is `role="option"` with flag (decorative) + country name + dial code as **text** (e.g. "United Kingdom +44"). Typically ~320px wide, virtualized when it holds ~240 entries.
*   **Search / filter field** — an optional text input at the top of the panel to filter countries by name or code ("ger", "+49"). Improves reach over pure typeahead for long lists.
*   **Number input** — the `<input type="tel" inputmode="tel" autocomplete="tel">` where digits are typed. Displays the _localized_ as-you-type formatted number; its underlying model value is E.164.
*   **Label** — a real `<label for>` above or beside, e.g. "Phone number". Not placeholder-only.
*   **Placeholder / format hint** — an example number _for the selected country_ (`(201) 555-0123` for US, `07400 123456` for GB), regenerated when the country changes.
*   **Validation icon + helper/error text** — a check on a valid E.164 number, an inline error ("Enter a valid UK mobile number") on invalid, wired via `aria-describedby` / `aria-invalid`.
*   **Extension field (optional)** — a separate small input for a PBX extension (`ext.`), kept distinct from the main number because E.164 does not carry extensions.
* * *

## 4\. Sizes / Scale / Density

The selector and number field share one height so the composite reads as a single control. The flag renders at a fixed aspect (4:3) regardless of field size.

| Size | Field height | Flag | Dial-code text | Padding (H) | Font | Use |
| ---| ---| ---| ---| ---| ---| --- |
| SM | 32px | 16×12px | 12px | 8px | 13px | Dense admin forms, CRM contact rows, compact checkout |
| MD | 40px | 20×15px | 14px | 12px | 14px | Default for most sign-up and contact forms |
| LG | 48px | 24×18px | 16px | 16px | 16px | Mobile-first primary flows, single-field pages, accessibility-forward UIs |

Tokens and rules that matter:

*   Height is driven by `--field-h-{sm,md,lg}`, not a magic number, so the phone field lines up pixel-for-pixel with siblings (email, name) in the same form.
*   **Touch target ≥ 44px** on the country trigger even at SM: expand the hit area with padding, because the trigger is small but frequently mis-tapped on mobile.
*   The **listbox panel** has its own density: option rows 36–44px tall (44px on touch), max-height ~320px with internal scroll, `--phone-panel-w: 20rem` default.
*   On narrow viewports (<400px), the country panel should go **full-width bottom-sheet** rather than a floating popover, so the search field and options stay tappable.
*   Reserve horizontal space for the _widest_ dial code you support (`+1-268`, `+298`) so the number field doesn't reflow when the country changes.
* * *

## 5\. States

*   **Empty (rest)** — no digits; placeholder shows a country-appropriate example number. Country defaults from IP/locale or an explicit prop, never assumed US.
*   **Focus (number field)** — visible focus ring on the whole composite container; `:focus-visible` so mouse clicks don't show the ring but Tab does.
*   **Typing / as-you-type** — each keystroke reformats the visible string via the country's formatter (spaces, dashes, parens appear as you go). The model value quietly normalizes toward E.164 in the background.
*   **Valid** — the number parses as a _possible and valid_ number for the selected country; show a subtle check, set `aria-invalid="false"`. Valid is country-specific, not "has 10 digits."
*   **Invalid / error** — number is impossible or invalid for the country (wrong length, wrong prefix). `aria-invalid="true"`, red border, specific message ("This isn't a valid German mobile number"). Never fire on every keystroke — validate on blur or after a debounce.
*   **Country panel open** — trigger has `aria-expanded="true"`, listbox visible, one option is the `aria-activedescendant`, typeahead active.
*   **Disabled** — whole composite non-interactive, reduced opacity, `cursor: not-allowed`, country locked.
*   **Read-only** — value shown, selectable/copyable, but not editable (e.g. a confirmed number on a review screen).
*   **Loading / verifying** — after "Send code," the field or its adjacent button shows a spinner and blocks re-submits while the SMS request is in flight (`aria-busy`).
*   **Autofilled** — browser filled the number from saved data; the country trigger must sync to match the autofilled `+` prefix, and the formatter must re-run so the display isn't a raw digit string.
* * *

## 6\. Types / Variants

*   **Combobox + national formatting (default).** Country selector on the left, national-format number on the right. The workhorse: international reach, familiar local formatting, E.164 under the hood.
*   **Auto-detect country.** Initial country inferred from browser locale, `navigator.language`, IP geolocation, or a SIM/`Intl` hint — still fully overridable. Reduces taps for the common case without hardcoding a market.
*   **Fixed / single-market.** No selector; the dial code is fixed (e.g. a US-only DMV form). Renders `+1` as static text and validates against one country. Correct _only_ when the market is genuinely single-country.
*   **Split fields (dial code + number as two controls).** A separate country/dial-code select and a separate number input, each independently labeled. Common in enterprise/legacy forms; more verbose but very screen-reader-legible.
*   **With inline validation feedback.** Adds a live valid/invalid indicator and possible-vs-valid messaging as the user types (debounced), plus a green check on a confirmed-valid E.164 number.
*   **With OTP / "send code" trigger.** Bundles a "Send verification code" button that hands the E.164 number to an SMS endpoint and transitions into a code-entry state. The variant most exposed to abuse (see §15).
*   **With extension.** Adds a small separate `ext.` input for PBX extensions, stored alongside the E.164 number (never inside it).
* * *

## 7\. When to Use (and When Not To)

**Use a Phone Input when:**

*   You collect a real, callable/textable phone number: sign-up, contact forms, account recovery, delivery/logistics contact, SMS-OTP flows.
*   Your audience is or could become international — which is nearly always true for anything on the public web.
*   You will send SMS or place calls to the number and therefore need clean E.164 storage.

**Don't use one / use something else when:**

*   You need a **numeric quantity** (age, count, price) → use a **Number Input** (`type="number"`, spinbutton).
*   You need a **fixed-format secret** (credit card, SSN, ZIP) → use a **masked input** with a static template.
*   You need **verification-code entry** (the 6-digit OTP itself) → use a dedicated **one-time-code input** (`autocomplete="one-time-code"`, segmented boxes), not a phone field.
*   The value is **not a phone number at all** (extension-only, internal ID) → a plain text or number field is honest and lighter.

Placement heuristics:

*   Put the country selector on the **leading edge** (left in LTR) so users set context before typing digits.
*   In a form, place phone after name/email in the natural identity block; don't isolate it.
*   On mobile, prefer the **bottom-sheet** country picker over a tiny floating menu, and keep the number field above the fold so the keyboard doesn't bury it.
* * *

## 8\. Across Design Systems

Same control, different philosophies. Notably, most large design systems do **not** ship a first-class phone component — they expose a text field and expect you to compose the country selector with `intl-tel-input` or `libphonenumber`. Knowing each system's building blocks is the real fluency.

*   **Material Design (Google).** No dedicated phone field; you compose an `<md-outlined-text-field type="tel">` with a leading `<md-outlined-select>` for the country. Material's guidance leans on `autofill` hints and a floating label. Android's own `PhoneNumberFormattingTextWatcher` does as-you-type formatting natively.
*   **Apple HIG (iOS/macOS).** `UITextField` with `.keyboardType = .phonePad` and `textContentType = .telephoneNumber` to unlock Contacts autofill and the numeric-with-symbols keypad. No stock country combobox; teams build one or use a library. SF Symbols supply the chevron.
*   **Fluent (Microsoft).** A `TextField` with `type="tel"`; country selection via a `Combobox` or `Dropdown`. Fluent emphasizes clear error text and the `aria-describedby` wiring, plus compact density for enterprise admin forms.
*   **Ant Design (enterprise).** No native phone field; the common pattern is `<Input>` with an `addonBefore={<Select>}` holding dial codes — Ant's addon slot is _designed_ for exactly this leading-selector composition. Validation via `Form.Item` rules.
*   **Tailwind / utility-first.** No prescribed component; you compose a flex row of a `<button>`\-driven listbox and an `<input type="tel">`, usually wrapping `libphonenumber-js` for parsing. Freedom plus the responsibility to get the a11y and E.164 handling right yourself.
*   **shadcn/Radix.** The country selector is a `Command` + `Popover` combobox (searchable, keyboard-complete, accessible by default from Radix), paired with a shadcn `Input`. This is currently the cleanest headless-behavior + owned-styling path, and community `PhoneInput` recipes build directly on it plus `react-phone-number-input`.
*   **Bootstrap 5.** An `input-group` with a `<select>` or dropdown as an `input-group-text` prepend, and a `form-control` `type="tel"`. Bootstrap ships the layout; formatting/validation is bolt-on (often `intl-tel-input`).

### 8b. What's trending in 2026

*   **Liquid Glass country pickers.** Apple's iOS 26 / macOS Tahoe material has pushed the country panel toward translucent, refracting bottom-sheets with a specular rim — pretty, but the flag/name/code text must still clear contrast against the blurred backdrop.
*   **Passkeys and silent verification eroding SMS-OTP.** As passkeys and platform silent-auth spread, the phone field is shifting from "primary auth factor" toward "contact + fallback," which changes how aggressively you gate the send-code button.
*   **On-device geolocation +** **`Intl`** **defaults.** Smarter country auto-detection from `Intl.Locale` and privacy-preserving region hints, replacing IP lookups.
*   **Autofill-first design.** Deep investment in `autocomplete="tel"` + `textContentType` so the OS fills the whole number and the UI just confirms it — reducing manual typing (and errors) to near zero on returning users.

### 9.1 HTML (semantic foundation with ARIA)

```html
<div class="phone-field" data-country="US">
  <label id="phone-label" for="phone-number">Phone number</label>

  <div class="phone-field__row">
    <!-- Country combobox: button opens a listbox -->
    <button type="button"
            class="phone-field__country"
            id="country-trigger"
            aria-haspopup="listbox"
            aria-expanded="false"
            aria-controls="country-listbox"
            aria-labelledby="phone-label country-trigger">
      <span class="flag" aria-hidden="true">🇺🇸</span>
      <span class="dial">+1</span>
      <span class="visually-hidden">United States, dialing code plus 1. Change country</span>
      <svg class="chevron" aria-hidden="true" viewBox="0 0 20 20"><path d="M5 8l5 5 5-5"/></svg>
    </button>

    <!-- The number itself: tel type + inputmode + autocomplete are all required -->
    <input type="tel"
           id="phone-number"
           name="phone"
           class="phone-field__input"
           inputmode="tel"
           autocomplete="tel"
           placeholder="(201) 555-0123"
           aria-describedby="phone-hint phone-error"
           aria-invalid="false" />
  </div>

  <!-- Popup listbox, rendered on open. aria-activedescendant tracks the highlighted option. -->
  <ul id="country-listbox" role="listbox" aria-label="Country" hidden>
    <li id="c-US" role="option" aria-selected="true">
      <span class="flag" aria-hidden="true">🇺🇸</span>
      <span class="name">United States</span><span class="dial">+1</span>
    </li>
    <li id="c-GB" role="option" aria-selected="false">
      <span class="flag" aria-hidden="true">🇬🇧</span>
      <span class="name">United Kingdom</span><span class="dial">+44</span>
    </li>
    <!-- …one option per country; flag decorative, name + dial code are real text -->
  </ul>

  <p id="phone-hint" class="phone-field__hint">Well text a verification code to this number.</p>
  <p id="phone-error" class="phone-field__error" role="alert" hidden></p>
</div>
```

Key HTML rules:

*   **`type="tel"`** **+** **`inputmode="tel"`** **+** **`autocomplete="tel"`** **together.** `type="tel"` sets semantics, `inputmode="tel"` summons the phone keypad on mobile, `autocomplete="tel"` unlocks OS/browser autofill from the contact card. Dropping any one degrades the experience.
*   **The flag is** **`aria-hidden`****.** The accessible name comes from real text (`visually-hidden` span + the option text), never the flag glyph alone.
*   **Never** **`type="number"`** — it strips leading zeros, chokes on `+`, and exposes a spinner that can silently mutate the value.

### 9.3 React + TypeScript (full reusable component)

```tsx
import { forwardRef, useId, useMemo, useState } from "react";
import {
  AsYouType,
  parsePhoneNumberFromString,
  getExampleNumber,
  type CountryCode,
} from "libphonenumber-js";
import examples from "libphonenumber-js/mobile/examples";

export interface PhoneInputProps {
  /** The stored value, always E.164 (e.g. "+14045550132"). */
  value: string;
  onChange: (e164: string, meta: { country: CountryCode; valid: boolean }) => void;
  defaultCountry?: CountryCode;
  disabled?: boolean;
  label?: string;
}

const COUNTRIES: { code: CountryCode; name: string; dial: string; flag: string }[] = [
  { code: "US", name: "United States", dial: "+1", flag: "🇺🇸" },
  { code: "GB", name: "United Kingdom", dial: "+44", flag: "🇬🇧" },
  { code: "NG", name: "Nigeria", dial: "+234", flag: "🇳🇬" },
  { code: "DE", name: "Germany", dial: "+49", flag: "🇩🇪" },
  // …full ISO 3166 list in production, sourced from libphonenumber metadata
];

export const PhoneInput = forwardRef<HTMLInputElement, PhoneInputProps>(function PhoneInput(
  { value, onChange, defaultCountry = "US", disabled, label = "Phone number" },
  ref
) {
  const [country, setCountry] = useState<CountryCode>(defaultCountry);
  const [open, setOpen] = useState(false);
  const [touched, setTouched] = useState(false);
  const errorId = useId();
  const hintId = useId();

  const meta = COUNTRIES.find((c) => c.code === country)!;

  // Display value is national/localized; the model value is E.164.
  const display = useMemo(() => {
    const parsed = value ? parsePhoneNumberFromString(value) : undefined;
    return parsed ? parsed.formatNational() : "";
  }, [value]);

  const placeholder = useMemo(
    () => getExampleNumber(country, examples)?.formatNational() ?? "",
    [country]
  );

  const validity = useMemo(() => {
    const parsed = value ? parsePhoneNumberFromString(value) : undefined;
    return parsed?.isValid() ?? false;
  }, [value]);

  function handleType(raw: string) {
    // As-you-type formats for display; parse to E.164 for the model.
    const formatter = new AsYouType(country);
    formatter.input(raw);
    const parsed = parsePhoneNumberFromString(raw, country);
    const e164 = parsed ? parsed.number : raw.replace(/[^\d+]/g, "");
    onChange(e164, { country, valid: parsed?.isValid() ?? false });
  }

  function pickCountry(c: CountryCode) {
    setCountry(c);
    setOpen(false);
    // Re-normalize the existing digits under the new country.
    const parsed = parsePhoneNumberFromString(value || "", c);
    onChange(parsed ? parsed.number : value, { country: c, valid: parsed?.isValid() ?? false });
  }

  const showError = touched && value.length > 0 && !validity;

  return (
    <div className="phone-field" data-invalid={showError} aria-disabled={disabled}>
      <label htmlFor={`${errorId}-input`}>{label}</label>
      <div className="phone-field__row">
        <button
          type="button"
          className="phone-field__country"
          aria-haspopup="listbox"
          aria-expanded={open}
          disabled={disabled}
          onClick={() => setOpen((o) => !o)}
        >
          <span className="flag" aria-hidden>{meta.flag}</span>
          <span className="dial">{meta.dial}</span>
          <span className="visually-hidden">{meta.name}, dialing code {meta.dial}. Change country</span>
        </button>
        <input
          ref={ref}
          id={`${errorId}-input`}
          type="tel"
          inputMode="tel"
          autoComplete="tel"
          disabled={disabled}
          value={display}
          placeholder={placeholder}
          aria-describedby={`${hintId} ${errorId}`}
          aria-invalid={showError}
          onChange={(e) => handleType(e.target.value)}
          onBlur={() => setTouched(true)}
        />
      </div>
      {open && (
        <ul role="listbox" aria-label="Country" className="phone-field__listbox">
          {COUNTRIES.map((c) => (
            <li
              key={c.code}
              role="option"
              aria-selected={c.code === country}
              onClick={() => pickCountry(c.code)}
            >
              <span className="flag" aria-hidden>{c.flag}</span>
              <span className="name">{c.name}</span>
              <span className="dial">{c.dial}</span>
            </li>
          ))}
        </ul>
      )}
      <p id={hintId} className="phone-field__hint">Well text a code to this number.</p>
      {showError && (
        <p id={errorId} role="alert" className="phone-field__error">
          Enter a valid {meta.name} phone number.
        </p>
      )}
    </div>
  );
});
```

Why this is the senior version: the **stored value is always E.164**, the **display is derived** national formatting, validity is **country-derived** (never a hardcoded length), and changing the country **re-normalizes** the existing digits instead of throwing them away.

### 9.4 Vanilla JavaScript (no framework, full keyboard)

```js
import { AsYouType, parsePhoneNumberFromString } from "libphonenumber-js";

const field = document.querySelector(".phone-field");
const trigger = field.querySelector("#country-trigger");
const listbox = field.querySelector("#country-listbox");
const input = field.querySelector("#phone-number");
const errorEl = field.querySelector("#phone-error");

let country = field.dataset.country || "US";
let activeIndex = 0;
const options = () => [...listbox.querySelectorAll('[role="option"]')];

// --- As-you-type formatting; model value kept on a data attribute ---
input.addEventListener("input", () => {
  const formatter = new AsYouType(country);
  const formatted = formatter.input(input.value);
  input.value = formatted;                                  // localized display
  const parsed = parsePhoneNumberFromString(input.value, country);
  field.dataset.e164 = parsed ? parsed.number : "";         // canonical model
  field.dataset.valid = parsed ? String(parsed.isValid()) : "false";
});

input.addEventListener("blur", () => {
  const parsed = parsePhoneNumberFromString(input.value, country);
  const ok = parsed?.isValid() ?? input.value === "";
  field.dataset.invalid = String(!ok);
  errorEl.hidden = ok;
  errorEl.textContent = ok ? "" : "Enter a valid phone number for this country.";
  input.setAttribute("aria-invalid", String(!ok));
});

// --- Country combobox: open/close + full keyboard ---
function openList() {
  listbox.hidden = false;
  trigger.setAttribute("aria-expanded", "true");
  setActive(options().findIndex((o) => o.getAttribute("aria-selected") === "true") || 0);
  listbox.focus();
}
function closeList() {
  listbox.hidden = true;
  trigger.setAttribute("aria-expanded", "false");
  trigger.focus();
}
function setActive(i) {
  const opts = options();
  activeIndex = (i + opts.length) % opts.length;
  opts.forEach((o, idx) => o.classList.toggle("is-active", idx === activeIndex));
  const el = opts[activeIndex];
  listbox.setAttribute("aria-activedescendant", el.id);
  el.scrollIntoView({ block: "nearest" });
}
function choose(i) {
  const el = options()[i];
  options().forEach((o) => o.setAttribute("aria-selected", "false"));
  el.setAttribute("aria-selected", "true");
  country = el.id.replace("c-", "");
  field.dataset.country = country;
  trigger.querySelector(".flag").textContent = el.querySelector(".flag").textContent;
```

```python
# main.py — FastAPI: validate + normalize to E.164, then rate-limit before any SMS
from fastapi import FastAPI, HTTPException, Request, Depends
from pydantic import BaseModel
import phonenumbers

app = FastAPI()

class PhonePayload(BaseModel):
    phone: str          # whatever the client sent — never trusted
    country: str | None = None   # ISO 3166 hint for national-format inputs

def normalize_e164(raw: str, region: str | None) -> str:
    try:
        parsed = phonenumbers.parse(raw, region)  # region needed if raw has no '+'
    except phonenumbers.NumberParseException:
        raise HTTPException(422, "Could not parse phone number")
    if not phonenumbers.is_valid_number(parsed):   # country-aware validity
        raise HTTPException(422, "Not a valid phone number")
    return phonenumbers.format_number(parsed, phonenumbers.PhoneNumberFormat.E164)

@app.post("/api/phone/verify")
async def start_verification(body: PhonePayload, request: Request, rl=Depends(rate_limit)):
    e164 = normalize_e164(body.phone, body.country)
    # Do NOT reveal whether e164 already maps to an account (enumeration defense).
    await queue_sms_otp(e164)                 # rate-limited per-number AND per-IP upstream
    return {"status": "sent"}                 # identical response for new and existing numbers
```

```dart
  ];

  void _validate(String raw) {
    final phone = PhoneNumber.parse(raw, callerCountry: _country);
    setState(() => _error = phone.isValid() ? null : 'Enter a valid phone number');
    // Model value (E.164): phone.international
  }

  @override
  Widget build(BuildContext context) {
    final meta = _countries.firstWhere((c) => c.$1 == _country);
    return Row(children: [
      Semantics(
        label: 'Country ${meta.$3}. Change country',
        child: DropdownButton<IsoCode>(
          value: _country,
          onChanged: (c) => setState(() => _country = c!),
          items: _countries
              .map((c) => DropdownMenuItem(value: c.$1, child: Text('${c.$2} ${c.$3}')))
              .toList(),
        ),
      ),
      Expanded(
        child: TextField(
          controller: _controller,
          keyboardType: TextInputType.phone,
          autofillHints: const [AutofillHints.telephoneNumber],
          onChanged: _validate,
          decoration: InputDecoration(hintText: '(201) 555-0123', errorText: _error),
        ),
      ),
    ]);
  }
}
```

## 10\. Accessibility

STANDALONE. The Phone Input is two accessibility problems in one: a text field (easy) and a **combobox with a flag** (where most implementations fail).

**Roles & ARIA:**

*   Number field: native `<input type="tel">`, wired with `aria-describedby` (hint + error) and `aria-invalid` on error.
*   Country trigger: `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls` pointing at the listbox. Its **accessible name is text** ("United States, dialing code plus 1. Change country"), never the flag alone.
*   Listbox: `role="listbox"`, each row `role="option"` with `aria-selected`, and `aria-activedescendant` on the listbox tracking the highlighted option.
*   **The flag is always** **`aria-hidden="true"`****.** Country name and dial code are real, screen-reader-readable text in every option.

**Keyboard map (country combobox):**

| Key | Action |
| ---| --- |
| Tab | Move into the country trigger, then into the number field (two stops) |
| Enter / Space (on trigger) | Open the listbox, focus the selected option |
| ArrowDown / ArrowUp | Move the active option within the open listbox |
| Home / End | Jump to first / last country |
| A–Z (typeahead) | Jump to the next country whose name starts with the typed run |
| Enter / Space (in list) | Select the active country, close, return focus to trigger |
| Escape | Close the listbox without changing selection, return focus to trigger |
| Tab (in list) | Close the listbox and move focus onward |

**Focus management:** opening the listbox moves focus (or virtual focus via `aria-activedescendant`) to the selected option; selecting or Escaping returns focus to the trigger. Changing country must **not** steal focus from the number field if the user changed it mid-typing.

**Contrast:** dial-code and country-name text ≥ 4.5:1; the field border and focus ring are non-text elements needing ≥ 3:1. Never signal invalid with red border alone — pair it with the `role="alert"` error text.

**Target size:** the country trigger and each option row ≥ 44×44px on touch, even when the visual chip is smaller.

**Reduced motion:** the panel open/close and any as-you-type shimmer collapse to instant under `prefers-reduced-motion: reduce`.

**Common failures specific to this component:**

*   Flag-only country labels → invisible to screen readers.
*   As-you-type formatting that fires `aria-live` on every keystroke → machine-gun announcements. Announce the _final_ value on blur, not intermediates.
*   Cursor jumping to the end when the formatter inserts a space/paren mid-edit → maddening for everyone, catastrophic for switch/AT users. Preserve caret position relative to digits.
*   `type="number"` used for phone → strips leading zeros, breaks `+`, exposes a spinner.
*   Error announced only visually with color, no `aria-invalid` / alert text.

## 11\. Innovative / Emerging Ideas

*   **WebOTP API auto-fill.** `navigator.credentials.get({ otp: { transport: ["sms"] } })` lets the browser read the incoming SMS code and fill the OTP field automatically — pair it with `autocomplete="one-time-code"` so the phone → code hop is zero-typing on Android/Chrome.
*   **Contact Picker API.** On supported mobile browsers, `navigator.contacts.select(["tel"])` lets a user pick their own number from the OS contact card instead of typing it, cutting entry errors to near zero.
*   **`Intl.Locale`** **+ region hints for smarter defaults (2026-era).** Replace IP-based country guessing with on-device `Intl.Locale().region` and privacy-preserving locale signals, so the default country is right more often without a network round-trip or location permission.
*   **Passkey-first, phone-as-fallback.** As passkeys become primary auth, the phone field's job shifts to recovery/contact — enabling lighter verification friction (and less SMS spend) for the common path while keeping OTP as a backstop.
*   **Server-driven "possible vs valid" hints.** Stream libphonenumber's _possible-length_ feedback as the user types ("keep going, UK mobiles are 10 digits") instead of a binary pass/fail only at the end.
* * *

## 12\. Conversion / UX Killers

*   **Hardcoded US 10-digit validation.** A `\d{10}` or `maxlength="10"` rule silently rejects every non-US number and a chunk of US ones (extensions, `+1` prefixes). It fails _quietly_ — no error log, just international users who can't sign up. Fix: derive validity from the selected country via libphonenumber, never a fixed length.
*   **Storing the display string instead of E.164.** Save `(404) 555-0132` and your SMS gateway rejects it, so the OTP never sends and the user is locked out. Fix: store `+14045550132`; format for display only.
*   **Wrong default country.** Defaulting to US for a user in Lagos forces an extra tap on every sign-up and invites mis-entries under the wrong dial code. Fix: detect from locale/IP, and make the selector obvious and fast.
*   **Caret jumps during as-you-type formatting.** Inserting a paren or space mid-string bounces the cursor to the end, so users delete and retype. Fix: reformat while preserving caret position relative to the digit count.
*   **No visible dial code / ambiguous country.** If the user can't see which country is active, they type a national number under the wrong code and it silently normalizes wrong. Fix: always show flag + dial code on the trigger.
*   **Validation firing on every keystroke.** Red error flashing before the user finishes the first digit reads as hostile. Fix: validate on blur or after a debounce; show _progress_ (possible-length) while typing, not failure.
*   **Blocking paste.** Users paste numbers from notes/contacts; a field that rejects paste or mangles pasted `+44 20…` loses them. Fix: accept any pasted format and normalize it.
*   **Tiny country trigger on mobile.** A sub-44px flag chip crammed against the number field guarantees mis-taps. Fix: 44px target, bottom-sheet picker on narrow screens.

## 13\. Advanced Patterns

*   **TypeScript-enforced country-value contract.** Use `CountryCode` from libphonenumber and a discriminated result so a valid submission _can't_ be built without an E.164 string:

```ts
type PhoneResult =
  | { status: "empty" }
  | { status: "invalid"; input: string; country: CountryCode }
  | { status: "valid"; e164: `+${string}`; country: CountryCode; national: string };
// Downstream code that sends SMS can only accept status: "valid",
// so an un-normalized string never reaches the gateway.
```

*   **Design-token tiering for the composite.** The field shares tokens with all other inputs, so a rebrand touches one line:

```css
:root {
  --field-border: #cbd5e1;          /* semantic */
  --field-bg: #fff;
  --focus: #5F2C82;                 /* Eminence */
  --error: #b42318;
  --phone-panel-w: 20rem;           /* component */
  --phone-flag-w: 20px;
  --phone-option-h: 40px;
}
.phone-field__row { border-color: var(--field-border); }
.phone-field__row:focus-within { border-color: var(--focus); }
```

*   **Deferred metadata loading.** libphonenumber's full metadata is ~140KB. Ship the `min` or `mobile` metadata bundle, and lazy-load the full country list (and per-region examples) only when the picker opens, so the initial form paint stays cheap.
*   **Optimistic country re-normalization.** When the user changes country mid-entry, re-parse the existing digits under the new region and keep them if still valid, instead of clearing the field — preserves work and avoids a rage-inducing wipe.

## 14\. Performance & Bundle Cost

*   **libphonenumber is the weight.** The full `libphonenumber-js` metadata is ~140KB min. Import the **`/mobile`** or **`/min`** metadata bundle and named functions (`parsePhoneNumberFromString`, not the whole namespace) so the bundler tree-shakes unused country data. This is the single biggest phone-field perf decision.
*   **Lazy-load the country list.** Don't ship 240 flag glyphs and names in the initial payload. Load the list — and the per-country example numbers — on first open of the picker, behind a dynamic `import()`.
*   **Virtualize the listbox.** A 240-row country list with flags is a lot of DOM. Windowing (react-window/virtual) keeps only visible rows mounted, so open is instant and scroll stays at 60fps.
*   **Compositor-only panel animation.** Animate the picker's open/close with `transform` and `opacity` only — never `height`/`top` — to avoid per-frame layout thrash, and drop it entirely under `prefers-reduced-motion`.
*   **Debounce validity computation.** Running `isValid()` on every keystroke for every field in a big form adds up; debounce it (or compute only on blur) so typing stays smooth.
* * *

## 15\. Security

STANDALONE. The Phone Input has a **real, money-shaped attack surface** because it feeds SMS-sending and account-recovery endpoints.

**Attack surface:**

*   **SMS pumping / toll fraud.** An unthrottled "send code" tied to the phone field lets an attacker script thousands of sends to premium-rate number ranges they control, and you pay per message. This is one of the most common real-world costs of a naive phone field. Defense: rate-limit **per phone number, per IP, and per account** on the server, cap sends per number per day, and add exponential backoff / CAPTCHA after a few attempts.
*   **Account enumeration.** A "this number is already registered" message (or a timing/response difference between known and unknown numbers) lets an attacker discover who has an account. Defense: return an **identical response** for new and existing numbers ("If that number is valid, we sent a code") and equalize timing.

**Server-side validation & normalization (non-negotiable):** the client's E.164 is a _hint_. Re-parse and re-validate on the server with the `phonenumbers` / libphonenumber library (§9.13), reject impossible/invalid numbers, and store only the server-normalized E.164. The client formatter is UX; the server is the source of truth. Never persist a client-supplied display string.

**XSS:** the phone value is user content that often gets echoed back ("We texted +1 404…") into confirmation screens, admin dashboards, and SMS bodies. Always render it as text / escape it; never interpolate a raw phone string into HTML or into an SMS template without encoding. A number field that stores `+1<script>` and an admin panel that renders it unescaped is a stored-XSS path.

**Authorization:** if the field gates a state-changing action (change-of-number, recovery), the endpoint must independently verify that _this authenticated user_ may bind _that_ number — the UI showing the field is not authorization. Re-authenticate for high-stakes number changes so a hijacked session can't silently reroute a victim's OTPs.

## 17\. Visual Styles

The same Phone Input, eleven skins. Behavior is identical across all of them; only the surface changes.

1. **Flat.** Single hairline border unifying the country chip and number field, a flat fill, a solid-color chevron; the open country list is a plain white card with a thin divider under the search field. Reads instantly, scales across a whole form.
2. **Material.** The composite is a filled/outlined text field with a floating "Phone number" label; the country selector is a leading `md-select` with a ripple on tap, and the country sheet rises with elevation shadow and a scrim behind it.
3. **Glassmorphism.** The field row is a translucent `backdrop-filter: blur()` panel over a vivid backdrop, the dial code and flag floating on frosted glass; keep the country-name text on a solid chip so it still clears contrast against the blur.
4. **Liquid Glass (2026).** The country bottom-sheet is Apple-iOS-26 refracting material with a specular rim and a sheen that shifts as the sheet settles; the selected-country chip picks up a subtle light-bend at its edge. Ensure name + dial-code text stays legible over the moving refraction.
5. **Neumorphism.** The field is a soft inset groove pressed into a same-color surface, the country chip a gently extruded pill; accent only, and add a real border on the trigger and options because the low-contrast surface otherwise swallows focus.
6. **Skeuomorphism.** The number field looks like an engraved LCD strip, the country selector a beveled physical button with a glossy flag "sticker" and an inner highlight; the open list resembles a stacked rolodex of country cards.
7. **Neo-Brutalism.** Thick black border on the whole composite, a hard offset drop-shadow, zero radius, and a loud dial-code chip in a clashing color; the country list is a stark bordered box with chunky highlighted rows. The heavy borders actually aid focus visibility.
8. **Claymorphism.** Big-radius puffy field with an inner top-light and soft bottom-shadow, the country chip a rounded clay pill; the picker is a squishy, friendly card with generously rounded option rows.
9. **Aurora / Gradient.** An animated multi-hue gradient rides the field border and the focus ring on a dark surface, the dial code glowing softly; honor `prefers-reduced-motion` by freezing the gradient, and check text contrast at every gradient stop.
10. **Minimal / Swiss.** No borders — just a baseline underline under the number, the dial code set in a tight grotesk, generous whitespace, and the country list as plain left-aligned type. Structure and typography do all the work.
11. **UJG Brand.** Goldenrod focus ring and dial-code accent on a deep Eminence/Night field, Methanerse for the label, a warm glow on `:focus-within`, and country option rows highlighting in translucent Goldenrod. The house default: confident, warm, high-contrast.

**Rule that never changes:** the style is skin; the behavior is the skeleton. The `type="tel"`/`inputmode`/`autocomplete` semantics, E.164 storage, country-derived validation, the combobox keyboard map, the focus ring, and the 44px target are identical across all eleven skins.
