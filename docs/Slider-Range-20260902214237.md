# Slider/Range

# The Slider/Range: A Senior Engineer's Complete Breakdown
The component that lets users select a value (or range) by dragging along a track. Here's everything from first principles to production code.

This doc follows the Private ([https://app.clickup.com/8495850/docs/838qa-81211/838qa-200531](https://app.clickup.com/8495850/docs/838qa-81211/838qa-200531)) and its visual styles are drawn from the Private ([https://app.clickup.com/8495850/docs/838qa-87871/838qa-200551](https://app.clickup.com/8495850/docs/838qa-87871/838qa-200551)).

* * *
## 1\. What a Slider Actually Is
A **slider** (range input) is a control that lets users select a numeric value (or range of values) by dragging a thumb along a track. It maps a physical gesture (drag) to a numeric output.

**Slider (this doc):** single thumb, one value. Volume, brightness, price max.
**Range slider:** dual thumbs, two values (min/max). Price range, date range, size filter.
**Progress bar:** looks similar but is NOT interactive. Display only.

The HTML `<input type="range">` is the native slider. It works but is notoriously hard to style cross-browser, which is why most design systems build custom.

* * *
## 2\. Why It Matters
**Natural for continuous values.** When the exact number matters less than the relative position (volume, brightness, zoom), a slider is more intuitive than typing.
**Filter UX.** Price range sliders in e-commerce are conversion-critical. A bad slider (laggy, imprecise, inaccessible) directly costs sales.
**Accessibility complexity.** A slider has one of the richest keyboard contracts of any form control: arrow keys for small steps, Page Up/Down for large steps, Home/End for min/max. Getting this right with a custom implementation is non-trivial.

* * *
## 3\. Anatomy
**Track:** the horizontal (or vertical) line/bar representing the full range.
**Fill/Active track:** the colored portion from min to the thumb (or between two thumbs).
**Thumb:** the draggable handle. The primary interaction target.
**Value label/tooltip (optional):** shows the current value, often appears on hover/drag.
**Tick marks (optional):** discrete steps marked on the track.
**Min/Max labels (optional):** text at the track endpoints.
**Input companion (optional):** a numeric input synced to the slider for precise entry.

* * *
## 4\. Sizes / Scale

| Token | Track H | Thumb | Use |
| ---| ---| ---| --- |
| S | 4px | 16px | Compact settings, inline |
| M | 6px | 20px | Default |
| L | 8px | 24px | Touch-primary, mobile |

The thumb must maintain ≥44px tap target regardless of visual size. Expand hit area with transparent padding.

* * *
## 5\. States
**Default:** track + thumb at current value.
**Hover:** thumb enlarges slightly or shows elevation.
**Active/Dragging:** thumb is pressed, value label appears, track fill updates in real-time.
**Focus:** visible focus ring on the thumb (keyboard users).
**Disabled:** muted colors, cursor-not-allowed, no interaction.
**Error:** (for form-embedded sliders) red track/thumb when value is invalid.

For range sliders:
**Overlap prevention:** thumbs can't cross each other (min thumb ≤ max thumb).
**Collision:** when thumbs are adjacent, they may merge or stack.

* * *
## 6\. Types / Variants
**Single slider:** one thumb, one value.
**Range slider:** two thumbs, min and max values.
**Stepped/Discrete:** snaps to defined steps (e.g. 0, 25, 50, 75, 100).
**Continuous:** any value in the range.
**Vertical:** orientation rotated 90° (volume, EQ, color pickers).
**With marks:** tick marks at intervals.
**With input:** paired with a numeric field for precise entry.

* * *
## 7\. When to Use (and When Not To)
**Use a slider when:**
*   The value is continuous and the approximate position matters more than precision
*   The range is bounded and known (0-100, $0-$500)
*   Visual feedback of "where in the range" is valuable
*   Touch interaction is primary

**Use something else when:**
*   Precision matters more than speed → Number input
*   The range is unbounded → Number input
*   There are only 2-5 options → Radio/Segmented control
*   The value is categorical, not numeric → Select/Dropdown

* * *
## 8\. Across Design Systems
**Material:** `Slider` with marks, range, discrete/continuous. M3 adds a value indicator bubble.
**Apple HIG:** `UISlider` / SwiftUI `Slider`. Simple, single-thumb only natively.
**Fluent:** `Slider` with vertical option and snap points.
**Ant Design:** `<Slider>` with range, marks, tooltip, vertical props.
**Radix:** `<Slider.Root>` with full keyboard support, multiple thumbs, orientation.
**HTML native:** `<input type="range">` — accessible out of the box but extremely difficult to style consistently.

### 9.3 React + TypeScript

```typescript
import { useRef, useState, useCallback } from "react";

interface SliderProps {
  min?: number; max?: number; step?: number;
  value?: number; defaultValue?: number;
  onChange?: (value: number) => void;
  label: string;
  disabled?: boolean;
}

export function Slider({ min = 0, max = 100, step = 1, value: controlledValue,
  defaultValue = 50, onChange, label, disabled }: SliderProps) {
  const [internal, setInternal] = useState(defaultValue);
  const value = controlledValue ?? internal;
  const percent = ((value - min) / (max - min)) * 100;
  const trackRef = useRef<HTMLDivElement>(null);

  const handleKey = useCallback((e: React.KeyboardEvent) => {
    let next = value;
    switch (e.key) {
      case "ArrowRight": case "ArrowUp": next = Math.min(max, value + step); break;
      case "ArrowLeft": case "ArrowDown": next = Math.max(min, value - step); break;
      case "PageUp": next = Math.min(max, value + step * 10); break;
      case "PageDown": next = Math.max(min, value - step * 10); break;
      case "Home": next = min; break;
      case "End": next = max; break;
      default: return;
    }
    e.preventDefault();
    setInternal(next); onChange?.(next);
  }, [value, min, max, step, onChange]);

  return (
    <div className="slider-container">
      <div className="slider" role="slider" tabindex={0}
           aria-valuemin={min} aria-valuemax={max} aria-valuenow={value}
           aria-label={label} aria-disabled={disabled || undefined}
           onKeyDown={handleKey} ref={trackRef}>
        <div className="slider__track">
          <div className="slider__fill" style={{ width: `${percent}%` }} />
          <div className="slider__thumb" style={{ left: `${percent}%` }} />
        </div>
      </div>
    </div>
  );
}
```

### 9.5 JavaScript (pointer-based drag)

```javascript
class SliderControl {
  constructor(el) {
    this.el = el;
    this.track = el.querySelector('.slider__track');
    this.fill = el.querySelector('.slider__fill');
    this.thumb = el.querySelector('.slider__thumb');
    this.min = parseFloat(el.getAttribute('aria-valuemin'));
    this.max = parseFloat(el.getAttribute('aria-valuemax'));
    this.step = parseFloat(el.dataset.step || 1);
    this.value = parseFloat(el.getAttribute('aria-valuenow'));

    el.addEventListener('pointerdown', (e) => this.startDrag(e));
    el.addEventListener('keydown', (e) => this.handleKey(e));
  }

  startDrag(e) {
    e.preventDefault();
    this.el.setPointerCapture(e.pointerId);
    this.updateFromPointer(e);

    const move = (ev) => this.updateFromPointer(ev);
    const up = (ev) => {
      this.el.releasePointerCapture(ev.pointerId);
      this.el.removeEventListener('pointermove', move);
      this.el.removeEventListener('pointerup', up);
    };
    this.el.addEventListener('pointermove', move);
    this.el.addEventListener('pointerup', up);
  }

  updateFromPointer(e) {
    const rect = this.track.getBoundingClientRect();
    const pct = Math.max(0, Math.min(1, (e.clientX - rect.left) / rect.width));
    const raw = this.min + pct * (this.max - this.min);
    const stepped = Math.round(raw / this.step) * this.step;
    this.setValue(stepped);
  }

  handleKey(e) {
    let next = this.value;
    switch (e.key) {
      case 'ArrowRight': case 'ArrowUp': next += this.step; break;
      case 'ArrowLeft': case 'ArrowDown': next -= this.step; break;
      case 'PageUp': next += this.step * 10; break;
      case 'PageDown': next -= this.step * 10; break;
      case 'Home': next = this.min; break;
      case 'End': next = this.max; break;
      default: return;
    }
    e.preventDefault();
    this.setValue(Math.max(this.min, Math.min(this.max, next)));
  }

  setValue(val) {
    this.value = val;
    const pct = ((val - this.min) / (this.max - this.min)) * 100;
    this.fill.style.width = `${pct}%`;
    this.thumb.style.left = `${pct}%`;
    this.el.setAttribute('aria-valuenow', val);
    this.el.setAttribute('aria-valuetext', this.formatValue(val));
    this.el.dispatchEvent(new CustomEvent('change', { detail: { value: val } }));
  }

  formatValue(val) {
    // Override for custom formatting ($, %, etc.)
    return String(val);
  }
}
```

### 9.7 Next.js (controlled with URL state)

// app/components/price-slider.tsx
"use client";
import { useRouter, useSearchParams } from "next/navigation";
import { Slider } from "@/components/slider";

export function PriceSlider() {
  const router = useRouter();
  const params = useSearchParams();
  const value = Number(params.get("maxPrice") || 200);

  const handleChange = (newValue: number) => {
    const newParams = new URLSearchParams(params);
    newParams.set("maxPrice", String(newValue));
    router.push(`?${newParams.toString()}`, { scroll: false });
  };

  return (
    <Slider label="Max price" min={0} max={1000} step={10}
            value={value} onChange={handleChange}
            formatValue={(v) => `$${v}`} />
  );
}

    if (slider) slider.setAttribute('aria-valuenow', String(this.value));
  }

  handleKey(e: KeyboardEvent) {
    let next = this.value;
    switch (e.key) {
      case 'ArrowRight': case 'ArrowUp': next += this.step; break;
      case 'ArrowLeft': case 'ArrowDown': next -= this.step; break;
      case 'PageUp': next += this.step * 10; break;
      case 'PageDown': next -= this.step * 10; break;
      case 'Home': next = this.min; break;
      case 'End': next = this.max; break;
      default: return;
    }
    e.preventDefault();
    this.value = Math.max(this.min, Math.min(this.max, next));
    this.dispatchEvent(new CustomEvent('change', { detail: { value: this.value } }));
  }

  startDrag(e: PointerEvent) {
    const slider = this.shadowRoot!.querySelector('.slider')! as HTMLElement;
    slider.setPointerCapture(e.pointerId);
    const track = this.shadowRoot!.querySelector('.track')! as HTMLElement;
    const update = (ev: PointerEvent) => {
      const rect = track.getBoundingClientRect();
      const pct = Math.max(0, Math.min(1, (ev.clientX - rect.left) / rect.width));
      const raw = this.min + pct * (this.max - this.min);
      this.value = Math.round(raw / this.step) * this.step;
      this.dispatchEvent(new CustomEvent('change', { detail: { value: this.value } }));
    };
    update(e);
    slider.addEventListener('pointermove', update);
    slider.addEventListener('pointerup', () => {
      slider.removeEventListener('pointermove', update);
    }, { once: true });
  }
}
customElements.define('ui-slider', UiSlider);

## 10\. Accessibility
**`role="slider"`** on the custom element (native `<input type="range">` has it implicitly). This is the ARIA role that tells AT "this is a draggable value control."

**Required ARIA attributes:** `aria-valuemin`, `aria-valuemax`, `aria-valuenow` (the numeric value), and `aria-valuetext` (a human-readable string like "$250" or "40%" so the screen reader speaks meaning, not just a number).

**`aria-label`** **or** **`aria-labelledby`** — the slider must have a name. "Volume," "Max price," "Brightness." Without it, AT announces "slider, 40" with no context.

**Keyboard map (the full contract):**

| Key | Action |
| ---| --- |
| Arrow Right / Up | Increase by one step |
| Arrow Left / Down | Decrease by one step |
| Page Up | Increase by a large step (10× step) |
| Page Down | Decrease by a large step |
| Home | Jump to min |
| End | Jump to max |

This is the slider keyboard contract from WAI-ARIA Authoring Practices. Skip any of these six and keyboard users can't operate the control properly.

**For range sliders (two thumbs):** each thumb is independently focusable. Tab moves between them. Each carries its own `aria-valuenow`/`aria-valuetext`. Announce the range contextually ("Min price $100, Max price $400").

**Focus visible:** the thumb shows a clear `:focus-visible` ring. Never `outline: none` without a replacement.

**Touch target ≥ 44px** on the thumb. The visible circle can be 20px; the tappable area must reach 44px via an expanded pseudo-element.

**`prefers-reduced-motion`****:** disable any thumb animations, tooltip transitions, or track fill animations. The control still works; it just doesn't animate.

**Contrast:** track fill vs. track background ≥ 3:1 (non-text element). Thumb vs. background ≥ 3:1. Value label text ≥ 4.5:1.

**Don't rely on drag as the only input.** The keyboard map IS the accessible interface. A slider that only works by pointer dragging is completely inaccessible to keyboard, switch, and voice-control users.

## 11\. Innovative / Emerging Ideas
*   **Haptic detents:** on mobile, subtle vibration at step boundaries
*   **Logarithmic scales:** for audio (dB) or price ranges with exponential distribution
*   **Gradient fill:** track color changes with value (blue-cold to red-hot)
*   **Collaborative cursors:** multiple users' thumbs visible on the same slider

* * *
## 12\. Conversion / UX Killers
*   **No value display:** users can't tell the exact number. Always show the value somewhere.
*   **Laggy updates:** slider thumb trails behind the finger/cursor. Use `requestAnimationFrame`.
*   **Impossible precision:** a 0-1000 range on a 300px track means each pixel = 3.3 units. Users can't pick exactly $247. Pair with a number input.
*   **No keyboard support:** custom sliders that only work with mouse/touch. Blocks keyboard and AT users entirely.
*   **Range thumbs that cross:** min exceeds max, breaking the filter logic.

* * *
## 13\. Advanced Patterns
**Slider + Input sync:** a numeric input beside the slider, both controlled by the same state. Typing in the input moves the thumb; dragging the thumb updates the input.

**Logarithmic mapping:** for audio or price ranges where low values need fine control and high values are coarse. Map the track position through a log function.

**Multi-thumb (3+):** EQ controls, color gradient stops. Each thumb is independently focusable.

* * *
## 14\. Performance & Bundle Cost
*   **Pointer events over mouse events.** `pointermove` captures touch and mouse in one handler.
*   **Throttle or rAF the value update** during drag to avoid re-rendering the entire form on every pixel.
*   **CSS custom properties** for fill/thumb position (`--value: 40%`) let CSS handle the visual update without JS DOM manipulation.

* * *
## 15\. Security
*   **Validate server-side.** A slider constrains the UI to min/max, but the POST body can be anything. Always validate range on the server.
*   **Don't trust step.** Users can submit values between steps via devtools.

* * *
## 16\. Senior-Level Checklist
*   `role="slider"` with `aria-valuemin/max/now/text`
*   All six keyboard controls (arrows, page, home/end)
*   Thumb tap target ≥44px
*   Fill/track contrast ≥ 3:1
*   Value displayed visually (tooltip or label)
*   Pairs with number input for precision when needed
*   Range thumbs can't cross
*   Drag uses `pointermove` + rAF (no jank)
*   Server validates range (don't trust client constraints)
*   `prefers-reduced-motion` disables any thumb/value animations
