# Context Menu

# The Context Menu: A Senior Engineer's Complete Breakdown
The right-click action menu positioned at the cursor. Here's everything from first principles to production code.

This doc follows the Private ([https://app.clickup.com/8495850/docs/838qa-81211/838qa-200531](https://app.clickup.com/8495850/docs/838qa-81211/838qa-200531)) and its visual styles are drawn from the Private ([https://app.clickup.com/8495850/docs/838qa-87871/838qa-200551](https://app.clickup.com/8495850/docs/838qa-87871/838qa-200551)).

* * *
## 1\. What a Context Menu Actually Is
A **context menu** is an action menu triggered by a secondary interaction (right-click on desktop, long-press on mobile) that appears at the cursor/touch position. It offers actions relevant to whatever the user right-clicked on.

**Context Menu (this doc):** position at cursor, triggered by right-click/long-press. Shows contextual actions.
**Dropdown Menu:** triggered by clicking a button, positioned relative to that button.
**Command Palette:** triggered by keyboard shortcut, positioned center-screen, has search.

The structure of items (actions, dividers, submenus, shortcuts) is identical to a Dropdown Menu. The difference is _trigger_ and _positioning_.

* * *
## 2\. Why It Matters
**Power-user acceleration.** Context menus let experienced users access actions faster without hunting for buttons. Right-click → action in two moves.
**Discoverability tradeoff.** Context menus are invisible until triggered. New users won't find them. They're an accelerator, never the only path to an action.
**Platform expectation.** Desktop users expect right-click to do something. A web app that suppresses the native context menu and provides nothing feels broken.

* * *
## 3\. Anatomy
Every context menu is composed of predictable parts:

**Trigger zone:** the area where right-click / long-press activates the menu. Unlike a dropdown (triggered by a specific button), the trigger is a _region_ — a card, a row, a canvas, a text selection.
**Menu panel:** the floating container that appears at the cursor position. Elevated with shadow, clipped to the viewport.
**Menu items:** individual actions. Each is a `role="menuitem"` with a label, optional leading icon, and optional trailing keyboard shortcut indicator.
**Dividers/Separators:** `role="separator"` lines grouping related actions.
**Submenus:** nested panels that expand on hover or ArrowRight from a parent item. The parent item shows a trailing chevron.
**Disabled items:** visible for discoverability but non-interactive (`aria-disabled="true"`), skipped by keyboard navigation.
**Destructive items:** red-colored for dangerous actions (Delete, Remove). Still follow normal hover/focus highlighting.
**Keyboard shortcut labels:** trailing text (⌘C, ⌫) showing the global shortcut for an action. Decorative — the shortcut works regardless of the menu being open.

* * *
## 4\. Sizes / Scale

| Token | Item H | Panel W | Font | Use |
| ---| ---| ---| ---| --- |
| S | 32px | 180–220px | 13px | Dense apps, power tools |
| M | 36px | 220–280px | 14px | Default |
| L | 44px | 260–320px | 15px | Touch-primary, mobile long-press |

Context menus tend compact (S/M) since they're power-user accelerators, but on touch devices the items MUST hit ≥44px for tap accuracy. The panel width is content-driven (longest label + icon + shortcut) with a min/max clamp.

* * *
## 5\. States
**Closed (hidden):** menu not rendered or `hidden`. The trigger zone is in its default state.
**Opening (long-press preview on mobile):** the user's finger is down for 300–500ms; haptic fires; the menu is about to appear. A brief delay distinguishes tap from long-press.
**Open:** menu visible at cursor/touch position. Focus moves to the first enabled item.
**Item default:** normal appearance within the open menu.
**Item hover / focused:** highlighted background. Keyboard focus and pointer hover share the same visual treatment.
**Item active (pressed):** brief press feedback before the action fires and the menu closes.
**Item disabled:** grayed out, `aria-disabled="true"`, skipped by arrow-key navigation.
**Item destructive:** red text/icon to signal danger. Still shows hover/focus highlight.
**Submenu trigger (has-children):** trailing chevron; on hover or ArrowRight, the submenu panel opens.
**Submenu open:** child panel visible beside the parent item; ArrowLeft closes it and returns focus to the parent.

* * *
## 6\. Types / Variants
**Standard:** flat list of actions for the target element.
**Grouped:** sections with dividers.
**With submenus:** nested menus for action categories.
**Table row context menu:** actions for a data row (Edit, Copy, Delete).
**Canvas context menu:** actions for a position (Paste here, Add node).
**Text selection context menu:** actions for selected text (Copy, Define, Translate).

* * *
## 7\. When to Use (and When Not To)
**Use when:**
*   Desktop app with power users who expect right-click
*   Canvas/editor apps where position matters ("paste here")
*   Supplementing existing button-triggered actions for faster access

**Don't use as the only path to actions.** Everything in a context menu must be accessible elsewhere (toolbar, dropdown, keyboard shortcut). Context menus are invisible until discovered.

* * *
## 8\. Across Design Systems
**Radix:** `ContextMenu` primitive with full keyboard support and submenus.
**shadcn:** `<ContextMenu>` built on Radix.
**Material:** no dedicated context menu component; teams build custom.
**Apple:** native `NSMenu` / UIKit context menus with system styling and haptics.
**Fluent:** uses the same `Menu` component with context trigger.

### 9.3 Vanilla JavaScript (full keyboard + positioning)

```javascript
class ContextMenuController {
  constructor(triggerEl, menuEl) {
    this.trigger = triggerEl;
    this.menu = menuEl;
    this.items = () => [...this.menu.querySelectorAll('[role="menuitem"]:not([aria-disabled="true"])')];
    this.focusedIndex = -1;

    // Right-click trigger
    this.trigger.addEventListener("contextmenu", (e) => { e.preventDefault(); this.open(e.clientX, e.clientY); });

    // Keyboard trigger (Shift+F10 or Menu key)
    this.trigger.addEventListener("keydown", (e) => {
      if (e.key === "ContextMenu" || (e.shiftKey && e.key === "F10")) {
        e.preventDefault();
        const rect = this.trigger.getBoundingClientRect();
        this.open(rect.left + rect.width / 2, rect.top + rect.height / 2);
      }
    });

    // Menu keyboard navigation
    this.menu.addEventListener("keydown", (e) => this.handleMenuKey(e));

    // Close on outside click
    document.addEventListener("pointerdown", (e) => {
      if (!this.menu.contains(e.target) && !this.menu.hidden) this.close();
    });
  }

  open(x, y) {
    this.menu.hidden = false;
    // Position with viewport collision detection
    const rect = this.menu.getBoundingClientRect();
    const vw = window.innerWidth, vh = window.innerHeight;
    const left = x + rect.width > vw ? x - rect.width : x;
    const top = y + rect.height > vh ? y - rect.height : y;
    this.menu.style.left = `${Math.max(4, left)}px`;
    this.menu.style.top = `${Math.max(4, top)}px`;
    this.focusItem(0);
  }

  close() {
    this.menu.hidden = true;
    this.trigger.focus();
  }

  focusItem(index) {
    const items = this.items();
    if (index < 0) index = items.length - 1;
    if (index >= items.length) index = 0;
    this.focusedIndex = index;
    items[index].focus();
  }

  handleMenuKey(e) {
    const items = this.items();
    switch (e.key) {
      case "ArrowDown": e.preventDefault(); this.focusItem(this.focusedIndex + 1); break;
      case "ArrowUp": e.preventDefault(); this.focusItem(this.focusedIndex - 1); break;
      case "Home": e.preventDefault(); this.focusItem(0); break;
      case "End": e.preventDefault(); this.focusItem(items.length - 1); break;
      case "Enter": case " ": e.preventDefault(); items[this.focusedIndex]?.click(); this.close(); break;
      case "Escape": case "Tab": e.preventDefault(); this.close(); break;
      default:
        if (e.key.length === 1) {
          const char = e.key.toLowerCase();
          const match = items.find((item, i) => i > this.focusedIndex && item.textContent.trim().toLowerCase().startsWith(char))
            || items.find(item => item.textContent.trim().toLowerCase().startsWith(char));
          if (match) this.focusItem(items.indexOf(match));
        }
    }
  }
}

// Initialize
new ContextMenuController(document.getElementById("context-target"), document.getElementById("ctx-menu"));
```

### 9.4 React + TypeScript (Radix)

```typescript
import * as ContextMenu from "@radix-ui/react-context-menu";
import { Edit, Copy, Clipboard, Trash, ChevronRight } from "lucide-react";

interface ContextMenuAction {
  label: string;
  icon?: React.ReactNode;
  shortcut?: string;
  destructive?: boolean;
  disabled?: boolean;
  onSelect: () => void;
}

interface Props {
  children: React.ReactNode;
  actions: ContextMenuAction[];
}

export function AppContextMenu({ children, actions }: Props) {
  return (
    <ContextMenu.Root>
      <ContextMenu.Trigger asChild>{children}</ContextMenu.Trigger>
      <ContextMenu.Portal>
        <ContextMenu.Content className="context-menu" sideOffset={2}>
          {actions.map((action, i) =>
            action.label === "---" ? (
              <ContextMenu.Separator key={i} className="ctx-separator" />
            ) : (
              <ContextMenu.Item
                key={action.label}
                className={`ctx-item ${action.destructive ? "ctx-item--destructive" : ""}`}
                onSelect={action.onSelect}
                disabled={action.disabled}
              >
                {action.icon && <span className="ctx-icon" aria-hidden="true">{action.icon}</span>}
                <span>{action.label}</span>
                {action.shortcut && <span className="ctx-shortcut">{action.shortcut}</span>}
              </ContextMenu.Item>
            )
          )}
        </ContextMenu.Content>
      </ContextMenu.Portal>
    </ContextMenu.Root>
  );
}
```

```typescript
      <li role="menuitem" tabindex="-1" (click)="select('copy')">Copy</li>
      <li role="separator"></li>
      <li role="menuitem" tabindex="-1" class="destructive" (click)="select('delete')">Delete</li>
    </ul>
  `,
  styleUrls: ["./context-menu.component.css"]
})
export class ContextMenuZoneComponent {
  open = false; x = 0; y = 0;
  @Output() action = new EventEmitter<string>();

  onContext(e: MouseEvent | KeyboardEvent) {
    if (e instanceof MouseEvent) { e.preventDefault(); this.x = e.clientX; this.y = e.clientY; }
    this.open = true;
  }
  close() { this.open = false; }
  select(action: string) { this.close(); this.action.emit(action); }

  @HostListener("document:click") onDocClick() { this.close(); }
}
```

```typescript
      </style>
      <slot></slot>
      <div class="menu" role="menu">
        ${items.map((i: any) => i.separator
          ? '<div role="separator"></div>'
          : `<button role="menuitem" tabindex="-1" class="${i.destructive ? 'destructive' : ''}" data-action="${i.action}">${i.label}</button>`
        ).join("")}
      </div>`;

    const slot = this.shadowRoot!.querySelector("slot")!;
    const menu = this.shadowRoot!.querySelector(".menu")! as HTMLElement;

    this.addEventListener("contextmenu", (e: Event) => {
      const me = e as MouseEvent;
      me.preventDefault();
      menu.style.top = `${me.clientY}px`; menu.style.left = `${me.clientX}px`;
      menu.classList.add("open");
      (menu.querySelector('[role="menuitem"]') as HTMLElement)?.focus();
    });

    document.addEventListener("click", () => menu.classList.remove("open"));
    menu.addEventListener("keydown", (e: Event) => {
      if ((e as KeyboardEvent).key === "Escape") menu.classList.remove("open");
    });

    menu.querySelectorAll("[data-action]").forEach(btn => {
      btn.addEventListener("click", () => {
        this.dispatchEvent(new CustomEvent("menu-action", { detail: (btn as HTMLElement).dataset.action, bubbles: true }));
        menu.classList.remove("open");
      });
    });
  }
}
```

### 9.13 Flutter

```dart
import 'package:flutter/material.dart';

class ContextMenuContent extends StatelessWidget {
  final Widget child;
  final VoidCallback onEdit;
  final VoidCallback onCopy;
  final VoidCallback onDelete;

  const ContextMenuContent({super.key, required this.child, required this.onEdit, required this.onCopy, required this.onDelete});

  @override
  Widget build(BuildContext context) {
    return GestureDetector(
      onSecondaryTapUp: (details) => _showMenu(context, details.globalPosition),
      onLongPressStart: (details) => _showMenu(context, details.globalPosition),
      child: child,
    );
  }

  void _showMenu(BuildContext context, Offset position) {
    showMenu(
      context: context,
      position: RelativeRect.fromLTRB(position.dx, position.dy, position.dx + 1, position.dy + 1),
      items: [
```

## 10\. Accessibility
Same keyboard contract as Dropdown Menu (arrows, enter, escape, type-ahead). Additional considerations:

**Don't suppress native context menu without replacement.** If you `preventDefault()` on `contextmenu`, you MUST provide an equivalent. Users rely on native context menus for copy/paste.

**Provide a keyboard trigger.** Shift+F10 or the Menu key should open the context menu. Right-click alone excludes keyboard users.

**Long-press on mobile** should have a haptic cue and a slight delay (300-500ms) to distinguish from tap.

* * *
## 11\. Innovative / Emerging Ideas
*   **AI-contextual actions:** menu items generated dynamically based on what the user right-clicked (right-click an image → "Remove background", "Alt text"; right-click text → "Translate", "Summarize")
*   **Inline previews:** hovering a menu item previews the action result before committing (hover "Rotate 90°" and the image previews rotated)
*   **Command palette integration:** typing in a context menu filters items like a mini command palette
*   **Collaborative context:** "See who edited this" or "Show history" as context-aware items in multiplayer apps
*   **Native-quality web context menus:** the `showContextMenu()` proposal for declarative, system-integrated web context menus

* * *
## 12\. Conversion / UX Killers
*   **Suppressing native context menu with nothing.** `preventDefault()` on `contextmenu` but no custom menu = users can't copy/paste. Rage-inducing.
*   **No keyboard trigger.** Right-click is mouse-only. Keyboard users need Shift+F10 or the Menu key, or they can never access these actions.
*   **Actions only available via context menu.** If "Delete" only lives in the right-click menu, most users will never find it. Every context-menu action must also exist in the toolbar or a visible dropdown.
*   **Wrong positioning.** Menu opens off-screen because collision detection wasn't implemented. Use Floating UI or manual viewport clamping.
*   **Too many items.** A 20-item context menu overwhelms. Group, prioritize, or use submenus for the long tail.
*   **No long-press on mobile.** Desktop-only context menus leave mobile users without access to those actions.

* * *
## 13\. Advanced Patterns
**Dynamic items based on selection state.** The menu changes based on what's selected: single item selected → "Edit, Delete"; multiple items → "Delete all, Move all"; nothing selected → "Paste, Select all." Build the items array from selection state, not a static config.

**Nested confirmation for destructive actions.** Instead of a separate confirm dialog, the "Delete" item expands inline to show "Confirm delete?" + "Cancel" within the menu itself. Faster, no modal interruption.

**Position at cursor with collision.** Use Floating UI's `computePosition` with `flip` and `shift` middleware so the menu never clips the viewport edge. On right-click near the bottom-right corner, the menu flips to open above-left instead of below-right.

**Virtual context menu for large lists.** In a data grid with 10,000 rows, don't render 10,000 context menu instances. Use one shared menu, repositioned and re-populated per right-click target via event delegation.

* * *
## 14\. Performance & Bundle Cost
*   **One menu instance, repositioned.** Never render a hidden menu per row/item. One shared menu moves to the cursor on trigger and updates its items from the target's data attributes.
*   **Portal the menu.** Render it at `document.body` level so ancestor `overflow: hidden` or `transform` can't clip it.
*   **Lazy render items.** If some items require async data (permissions check, clipboard state), render the menu immediately with a skeleton/spinner for those items, then fill them in.
*   **Exit animation cleanup.** If using a fade-out, unmount the DOM after the animation ends. Don't leave invisible menus accumulating in the tree.

* * *
## 15\. Security
*   **CSRF on destructive actions.** A context menu "Delete" fires a server request. That request needs the same CSRF protection as any button click. The casual trigger (right-click) doesn't reduce the security requirement.
*   **Authorization per item.** Don't show "Admin: Force delete" to non-admins. Filter menu items by the user's permissions _before_ rendering, and re-check server-side on the action.
*   **Don't expose sensitive data in menu labels.** A context menu that shows "Delete user [john@company.com](mailto:john@company.com)" leaks PII if the menu is screenshot-able or announced by AT in a shared screen. Use IDs internally, human names only where appropriate.

* * *
## 16\. Senior-Level Checklist
*   `role="menu"` + `role="menuitem"` structure (same as Dropdown Menu)
*   Full keyboard contract: arrows, Enter, Escape, type-ahead, Home/End
*   Keyboard trigger exists (Shift+F10 / Menu key) — not mouse-only
*   Native context menu not suppressed without a replacement
*   Positioned at cursor with viewport collision detection (flip + shift)
*   Focus moves into menu on open, returns to trigger zone on close
*   Long-press on touch with haptic feedback (300-500ms delay)
*   All actions ALSO accessible via toolbar/dropdown elsewhere (never the only path)
*   Disabled items `aria-disabled`, skipped by keyboard
*   Destructive items visually distinct + confirmed before execution
*   Items ≥44px on touch devices
*   One shared menu instance, not one per target (perf)
*   Server re-checks auth on every action the menu fires

## 17\. Visual Styles
The context menu panel is styled identically to Dropdown Menu across all eleven visual languages — same elevation, radius, item treatment. The only difference is positioning (at cursor vs. anchored to a button). **Style is skin; the keyboard contract, focus management, and 44px touch targets never change.**

**Flat:** solid dark panel, crisp border, no shadow depth. Clean and instant.
**Material:** elevated paper surface (shadow depth 8–16dp), ripple on item hover, rounded corners.
**Glassmorphism:** translucent panel with `backdrop-filter: blur()` over the content beneath. Guard item text contrast hard.
**Liquid Glass (2026):** refractive translucent panel with a specular rim — Apple's native macOS/iOS context menu look. SwiftUI emits it natively; web approximates with layered highlights.
**Neumorphism:** panel raised from a soft same-color surface with dual light/dark shadows. Items highlight with inner shadow.
**Skeuomorphism:** drop shadow, subtle gradient on the panel header, beveled dividers. The "real menu" look.
**Neo-Brutalism:** thick black border, hard offset shadow, bold mono item text, zero radius.
**Claymorphism:** puffy rounded panel, big radius, soft glow on hovered items. Friendly.
**Aurora / Gradient:** panel border or background is an animated gradient on dark. Premium; honor `prefers-reduced-motion`.
**Minimal / Swiss:** no shadow, thin single-pixel border, tight spacing, sharp typography. Maximum information density.
**UJG Brand:** Night panel with Eminence border, Goldenrod hover highlight on items, warm glow on the active item. The house default.
