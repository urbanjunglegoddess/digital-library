## 1\. What a Command Palette Actually Is
A **command palette** (command bar, quick actions, Cmd+K) is a centered modal with a search input that lets users find and execute actions, navigate to pages, or search content by typing. It's the keyboard-first power tool.

**Command Palette (this doc):** keyboard-triggered, centered, searchable list of actions and destinations.
**Dropdown Menu:** button-triggered, positioned at trigger, pre-defined action list.
**Search Bar:** always-visible input, searches content only (not actions).
**Spotlight/Omnibar:** OS-level command palette (macOS Spotlight, Windows Run).
* * *

## 2\. Why It Matters
**Power-user acceleration.** One shortcut (Cmd+K) accesses everything: navigation, actions, settings, search. Experienced users live in the command palette.
**Keyboard-first UX.** For apps with many features, clicking through menus is slow. Typing "delete project" is instant.
**Discoverability paradox.** The palette surfaces features users didn't know existed (type "theme" and find a dark mode toggle). It's both a shortcut AND a discovery tool.
* * *

## 3\. Anatomy
**Backdrop/Overlay:** dimmed background (usually lighter than a modal backdrop).
**Panel:** centered container, typically 560-640px wide.
**Search input:** the text field at the top. Always auto-focused on open.
**Results list:** filtered items grouped by category (Actions, Pages, Recent).
**Item:** icon + label + optional description + keyboard shortcut indicator.
**Group headers:** category labels ("Actions", "Navigation", "Recent").
**Footer (optional):** keyboard hints (arrows to navigate, enter to select, esc to close).
**Loading state:** spinner or skeleton while results fetch.
**Empty state:** "No results for \[query\]."
* * *

## 4\. Sizes / Scale

| Token | Width | Max Height | Input H | Item H |
| ---| ---| ---| ---| --- |
| Default | 560-640px | 60vh | 48px | 40-44px |
| Compact | 480px | 50vh | 40px | 36px |

On mobile (< 640px), the palette goes full-width with top positioning.
* * *

## 5\. States
**Closed:** not visible.
**Open (empty):** input focused, showing recent items or suggestions.
**Typing:** results filter in real-time as user types.
**Results shown:** grouped list of matches.
**No results:** empty state message.
**Loading:** async results being fetched.
**Item focused:** keyboard highlight on a result.
**Executing:** selected action is running (brief loading state before closing).
* * *

## 6\. Types / Variants
**Action palette:** executes commands (toggle theme, create project, logout).
**Navigation palette:** goes to pages/routes.
**Search palette:** searches content (docs, tasks, files).
**Hybrid (most common):** all three combined, grouped by type.
**Scoped:** typing a prefix filters to a category ("/ pages", "> actions").
**Nested/Multi-step:** selecting an item opens a sub-list ("Move to..." → list of destinations).
* * *

## 7\. When to Use (and When Not To)
**Use when:**
*   App has many features, pages, or actions
*   Power users need keyboard-first access
*   You want to centralize search + actions in one place

**Don't use:**
*   As the only way to access features (novices won't find it)
*   For simple apps with < 10 actions (overkill)
*   On mobile as primary navigation (touch users won't trigger Cmd+K)
* * *

## 8\. Across Design Systems
**cmdk (pacocoursey):** the React standard. Used by Vercel, Linear, Raycast.
**Kbar:** another React command palette library.
**Ninja Keys:** web component, framework-agnostic.
**VS Code:** the original modern command palette (Cmd+Shift+P).
**Raycast/Alfred:** native macOS command palettes.
**Linear:** the gold standard for command palette UX in a web app.

### 9.1 React (cmdk pattern)

```typescript
import { Command } from "cmdk";

export function CommandPalette({ open, onClose }: { open: boolean; onClose: () => void }) {
  return (
    <Command.Dialog open={open} onOpenChange={(o) => !o && onClose()} label="Command palette">
      <Command.Input placeholder="Type a command or search..." />
      <Command.List>
        <Command.Empty>No results found.</Command.Empty>
        <Command.Group heading="Actions">
          <Command.Item onSelect={() => { createProject(); onClose(); }}>
            Create project
          </Command.Item>
          <Command.Item onSelect={() => { toggleTheme(); onClose(); }}>
            Toggle dark mode
          </Command.Item>
        </Command.Group>
        <Command.Group heading="Navigation">
          <Command.Item onSelect={() => { navigate("/settings"); onClose(); }}>
            Settings
          </Command.Item>
        </Command.Group>
      </Command.List>
    </Command.Dialog>
  );
}

// Trigger
useEffect(() => {
  const handler = (e: KeyboardEvent) => {
    if (e.key === "k" && (e.metaKey || e.ctrlKey)) { e.preventDefault(); setOpen(true); }
  };
  document.addEventListener("keydown", handler);
  return () => document.removeEventListener("keydown", handler);
}, []);
```

### 9.2 Keyboard contract

```plain
Global:
  Cmd+K / Ctrl+K → open palette

Palette open:
  Escape → close (or go back one level if nested)
  ArrowDown → next item
  ArrowUp → previous item
  Enter → execute selected item
  Type → filter results
  Backspace (empty input) → go back one level if nested
```

### 9.7 Vue 3

```plain
<script setup lang="ts">
import { ref, onMounted, onUnmounted, computed } from 'vue';

const open = ref(false);
const query = ref('');
const selectedIndex = ref(0);

interface CmdItem { label: string; action: () => void; group: string; shortcut?: string; }
const items: CmdItem[] = [
  { label: 'Dashboard', action: () => router.push('/dashboard'), group: 'Navigation' },
  { label: 'Settings', action: () => router.push('/settings'), group: 'Navigation', shortcut: '⌘,' },
  { label: 'Create project', action: () => createProject(), group: 'Actions', shortcut: '⌘N' },
];

const filtered = computed(() => items.filter(i => i.label.toLowerCase().includes(query.value.toLowerCase())));

function handleKey(e: KeyboardEvent) {
  if (e.key === 'k' && (e.metaKey || e.ctrlKey)) { e.preventDefault(); open.value = !open.value; }
}

onMounted(() => document.addEventListener('keydown', handleKey));
onUnmounted(() => document.removeEventListener('keydown', handleKey));

function select(item: CmdItem) { item.action(); open.value = false; query.value = ''; }
function handleListKey(e: KeyboardEvent) {
  if (e.key === 'ArrowDown') { e.preventDefault(); selectedIndex.value = (selectedIndex.value + 1) % filtered.value.length; }
  if (e.key === 'ArrowUp') { e.preventDefault(); selectedIndex.value = (selectedIndex.value - 1 + filtered.value.length) % filtered.value.length; }
  if (e.key === 'Enter') { select(filtered.value[selectedIndex.value]); }
  if (e.key === 'Escape') { open.value = false; }
}
</script>

<template>
  <Teleport to="body">
    <div v-if="open" class="cmd-palette__backdrop" @click="open = false"></div>
    <div v-if="open" class="cmd-palette" role="dialog" aria-modal="true" aria-label="Command palette"
         @keydown="handleListKey">
      <input v-model="query" placeholder="Type a command..." class="cmd-palette__input" autofocus
             role="combobox" aria-expanded="true" aria-controls="cmd-list" />
      <div id="cmd-list" role="listbox" class="cmd-palette__list">
        <div v-for="(item, i) in filtered" :key="item.label" role="option"
             :aria-selected="i === selectedIndex" class="cmd-palette__item"
             @click="select(item)">
          {{ item.label }}
          <kbd v-if="item.shortcut" class="cmd-palette__item-shortcut">{{ item.shortcut }}</kbd>
        </div>
        <div v-if="filtered.length === 0" class="cmd-palette__empty">No results found.</div>
      </div>
    </div>
  </Teleport>
</template>
```

## 10\. Accessibility
A command palette is a modal combobox layered on a dialog — the most ARIA-dense pattern in most apps. Nail the roles, the keyboard model, and focus handling, or it's simply unusable for keyboard-only and screen-reader users.

### 10.1 ARIA roles (dialog + combobox + listbox)
**Panel:** `role="dialog"` + `aria-modal="true"` + `aria-label="Command palette"`.
**Input:** `role="combobox"`, `aria-expanded="true"` while results show, `aria-controls="cmd-list"` pointing at the listbox, and `aria-activedescendant="item-3"` pointing at the currently highlighted option.
**Results container:** `role="listbox"` with `id="cmd-list"`.
**Each result:** `role="option"` with a unique `id`; `aria-selected="true"` on the highlighted one only (exactly one at a time).
**Group headings:** mark the visible label `role="presentation"`; wrap options in `role="group"` + `aria-label` if you need them grouped semantically.
**Live region:** an `aria-live="polite"` node that announces the result count ("5 results") whenever the list updates.

The load-bearing idea: **`aria-activedescendant`** **keeps real DOM focus on the input** while the highlight moves through options. The user keeps typing; the screen reader announces each highlighted option without focus ever leaving the text field.

### 10.2 Keyboard map
Command Palette is fully interactive — every one of these must work without a mouse.

| Key | Context | Action |
| ---| ---| --- |
| Cmd/Ctrl + K | Global | Open the palette |
| Type (typeahead) | Open | Filter results live; reset highlight to the first match |
| ArrowDown | Open | Highlight next option (wraps to first) |
| ArrowUp | Open | Highlight previous option (wraps to last) |
| Home / End | Open | Jump to first / last option |
| Enter | Open | Execute the highlighted option |
| Escape | Open | Close palette (or step back one level if nested) |
| Backspace | Empty input, nested | Step back one level |
| Tab / Shift+Tab | Open | Cycle focus inside the dialog only — never escapes to the page |

**Focus trap:** while open, Tab and Shift+Tab cycle only through focusable elements inside the dialog; the app behind is made inert (`inert` attribute, or `aria-hidden="true"` on the app root).

### 10.3 Focus management
**On open:** move focus to the search input immediately, and save a reference to the element that triggered it (`document.activeElement`).
**While open:** focus stays pinned to the input; highlighting is virtual via `aria-activedescendant`.
**On close:** **return focus to the trigger** — the exact element that had focus before opening. Never let focus fall to `<body>`; keyboard users lose their place in the page.

### 10.4 Visual accessibility
**Contrast:** body text ≥ 4.5:1 against the panel; the highlighted-option background must stay ≥ 3:1 against the resting row background so low-vision users can see the selection — a faint hover tint alone fails.
**Selection isn't color-only:** pair the highlight background with a non-chromatic cue (left border, checkmark, or bolder text) for color-blind users.
**Target size:** result rows ≥ 44×44px effective touch target on mobile (the 40–44px item height in §4 clears this); apply the same to the close affordance and any inline buttons.
**Reduced motion:** honor `prefers-reduced-motion: reduce` — drop the open/close scale-and-fade, backdrop-blur transition, and list animation; show and hide instantly (the CSS in §9.3 already stubs this).
**Zoom / reflow:** the panel uses `max-width` + viewport units so it stays usable at 200% zoom and on narrow viewports without clipping.

### 10.5 Common failures
*   **Focus never returns to the trigger** on close — the single most common bug.
*   **Real DOM focus moves to each option** instead of using `aria-activedescendant`, so the input loses focus and typeahead breaks.
*   **No focus trap** — Tab leaks to the page behind the backdrop.
*   **Result count never announced** — screen-reader users don't know the list changed.
*   **Highlight is color-only** and too low-contrast to perceive.
*   **Escape doesn't close** (or closes the whole app instead of just the palette).
*   **Motion isn't gated** behind `prefers-reduced-motion`, triggering vestibular discomfort.

## 11\. Innovative / Emerging Ideas
*   **AI-powered:** natural language commands ("schedule a meeting with Sarah tomorrow")
*   **Fuzzy matching:** typo-tolerant search (fzf-style scoring)
*   **Recent + Frequent:** personalized results based on usage patterns
*   **Multiplayer:** see what teammates are doing in real-time within the palette
* * *

## 12\. Conversion / UX Killers
*   **Slow results:** any perceptible lag while typing kills the experience. Debounce ≤ 100ms.
*   **No keyboard hints:** users don't know how to navigate the results
*   **Too many results:** 50 items with no grouping. Group and limit to 5-8 per category.
*   **No recent/suggested items:** opening to a blank state with no guidance
*   **Actions that don't close the palette:** user executes, palette stays open confusingly
* * *

## 13\. Advanced Patterns
**Nested commands:** "Move to..." opens a sub-list of destinations. Backspace returns to parent.
**Scoped search prefixes:** "/" for pages, ">" for actions, "@" for users.
**Server-side search:** for large datasets, debounced API calls with loading state.
**Keyboard shortcut registration:** each action can register a global shortcut displayed in the palette.
* * *

## 14\. Performance & Bundle Cost
*   **Client-side fuzzy search** (fuse.js, cmdk's built-in) for local items.
*   **Server search for large datasets** with debounced requests.
*   **Virtual scrolling** if result list can exceed 50 items.
*   **Lazy load the palette** — don't include it in the initial bundle. Load on first Cmd+K.
* * *

## 15\. Security
*   **Scope results to user permissions.** Don't show actions/pages the user can't access.
*   **Rate-limit server search** to prevent enumeration attacks.
*   **Sanitize results** if they include user-generated content (titles, descriptions).
* * *

## 16\. Senior-Level Checklist
*   Cmd+K / Ctrl+K global trigger
*   `role="dialog"` + combobox ARIA pattern
*   `aria-activedescendant` for item focus
*   Results grouped and limited per category
*   Fuzzy/typo-tolerant matching
*   Recent items shown on empty input
*   ≤ 100ms perceived response time
*   Nested commands with back navigation
*   Focus returns to original element on close
*   Results scoped to user permissions

## 17\. Visual Styles
**Flat:** solid panel, clean border, no shadow.
**Material:** elevated surface with M3 rounded corners and shadow.
**Glassmorphism:** frosted translucent panel over blurred content.
**Liquid Glass:** refractive panel with specular rim. The macOS Spotlight look.
**Neumorphism:** panel raised from soft background.
**Skeuomorphism:** textured panel with inner shadow on input.
**Neo-Brutalism:** thick border, hard offset shadow.
**Claymorphism:** puffy panel, rounded items.
**Aurora/Gradient:** panel border or input focus ring is animated gradient.
**Minimal/Swiss:** hairline border, no shadow, maximum whitespace.
