# Dropdown Menu

# The Dropdown Menu: A Senior Engineer's Complete Breakdown
The action menu that appears on click and offers a list of commands. Here's everything from first principles to production code.

This doc follows the Private ([https://app.clickup.com/8495850/docs/838qa-81211/838qa-200531](https://app.clickup.com/8495850/docs/838qa-81211/838qa-200531)) and its visual styles are drawn from the Private ([https://app.clickup.com/8495850/docs/838qa-87871/838qa-200551](https://app.clickup.com/8495850/docs/838qa-87871/838qa-200551)).

* * *
## 1\. What a Dropdown Menu Actually Is
A **dropdown menu** (action menu, command menu) is a list of actions that appears when triggered by a button, and disappears after a selection or outside click. It answers "what can I do to this thing?"

Critical distinctions:

**Dropdown Menu (this doc):** triggered by a button, shows actions (Edit, Delete, Share). The user does something.
**Select/Dropdown:** a form input that picks a value. The user chooses a data value. Different component entirely.
**Context Menu:** same structure but triggered by right-click at cursor position.
**Popover:** a generic container that can hold anything. A dropdown menu is a popover containing a list of actions.

* * *
## 2\. Why It Matters
**Information hiding.** Menus let you offer many actions without cluttering the UI. The "..." or kebab button hides 5-10 actions that would overwhelm the surface.
**Keyboard navigation is the contract.** A dropdown menu that only works with a mouse is broken. Arrow keys to navigate, Enter to select, Escape to close. This is the `role="menu"` contract from WAI-ARIA.
**Focus management is the hard part.** On open, focus moves into the menu. On close, focus returns to the trigger. On select, focus returns AND the action fires. Getting this loop right is the whole challenge.

* * *
## 3\. Anatomy
**Trigger button:** the element that opens the menu (kebab icon, "Actions" button, icon button).
**Menu container:** the floating panel with elevation/shadow.
**Menu items:** individual actions. Each is selectable.
**Icons (optional):** leading icons per item for quick scanning.
**Keyboard shortcuts (optional):** trailing Kbd indicators (Cmd+D).
**Dividers:** horizontal rules separating groups of related actions.
**Submenus (optional):** nested menu that opens on hover/arrow-right.
**Disabled items:** grayed out, not selectable, but visible for discoverability.
**Destructive items:** red-colored for dangerous actions (Delete, Remove).

* * *
## 4\. Sizes / Scale

| Token | Item H | Panel W | Font | Use |
| ---| ---| ---| ---| --- |
| S | 32px | 180-220px | 13px | Compact, dense tables |
| M | 40px | 220-280px | 14px | Default |
| L | 48px | 260-320px | 15px | Touch-primary |

Menu items need ≥44px height on touch devices.

* * *
## 5\. States
**Closed:** menu not visible, trigger in default state.
**Open:** menu visible, focus inside.
**Item default:** normal appearance.
**Item hover/focused:** highlighted (background tint). Keyboard focus and hover share the same visual.
**Item active/pressed:** briefly shows press state before action fires.
**Item disabled:** grayed, skipped by keyboard navigation.
**Item destructive:** red text/icon, still follows hover/focus highlighting.
**Submenu open:** a child menu expanded from a parent item.

* * *
## 6\. Types / Variants
**Simple menu:** flat list of actions.
**Grouped menu:** sections separated by dividers with optional group headers.
**Menu with icons:** leading icons on each item.
**Menu with shortcuts:** trailing keyboard shortcut indicators.
**Menu with submenus:** nested menus that expand on hover or arrow-right.
**Checkbox menu:** items that can be toggled on/off (view options).
**Radio menu:** items where only one can be active (sort order).

* * *
## 7\. When to Use (and When Not To)
**Use a dropdown menu when:**
*   You have 3+ actions that would clutter the surface
*   Actions are contextual to a specific item (row actions, card actions)
*   Secondary actions that don't need primary prominence

**Use something else when:**
*   Selecting a form value → Select component
*   Only 1-2 actions → show them directly as buttons
*   Navigation links → Nav component (menus trigger actions, not navigation... usually)
*   Complex content in the popup → Popover or Dialog

* * *
## 8\. Across Design Systems
**Material:** `Menu` component anchored to a button. Uses `role="menu"` and `role="menuitem"`.
**Apple HIG:** `Menu` (SwiftUI) / `UIMenu`. Native contextual menus with system styling.
**Fluent:** `Menu` with `MenuTrigger`, `MenuPopover`, `MenuList`, `MenuItem` composition.
**Radix:** `DropdownMenu` primitive with full keyboard support, submenus, checkbox/radio items.
**shadcn:** `<DropdownMenu>` built on Radix. The go-to for React projects.
**Ant Design:** `<Dropdown>` with `menu` prop containing items array.

### 9.2 Keyboard contract

```plain
Trigger focused:
  Enter/Space/ArrowDown → open menu, focus first item
  ArrowUp → open menu, focus last item

Menu open:
  ArrowDown → next item (wraps)
  ArrowUp → previous item (wraps)
  Home → first item
  End → last item
  Enter/Space → activate item, close menu
  Escape → close menu, return focus to trigger
  Tab → close menu, move focus naturally
  Type-ahead → jump to item starting with typed letter

Submenu:
  ArrowRight → open submenu, focus first child
  ArrowLeft → close submenu, return to parent item
```

### 9.5 JavaScript (vanilla, full keyboard)

```javascript
class DropdownMenu {
  constructor(container) {
    this.container = container;
    this.trigger = container.querySelector('[aria-haspopup]');
    this.menu = container.querySelector('[role="menu"]');
    this.items = [...this.menu.querySelectorAll('[role="menuitem"]:not([aria-disabled="true"])')];
    this.isOpen = false;
    this.focusedIndex = -1;

    this.trigger.addEventListener('click', () => this.toggle());
    this.trigger.addEventListener('keydown', (e) => this.handleTriggerKey(e));
    this.menu.addEventListener('keydown', (e) => this.handleMenuKey(e));
    document.addEventListener('click', (e) => { if (!this.container.contains(e.target)) this.close(); });
  }

  toggle() { this.isOpen ? this.close() : this.open(); }

  open() {
    this.menu.hidden = false;
    this.trigger.setAttribute('aria-expanded', 'true');
    this.isOpen = true;
    requestAnimationFrame(() => this.menu.classList.add('is-open'));
    this.focusItem(0);
  }

  close() {
    this.menu.classList.remove('is-open');
    this.trigger.setAttribute('aria-expanded', 'false');
    this.isOpen = false;
    this.trigger.focus();
    // Wait for animation, then hide
    setTimeout(() => { if (!this.isOpen) this.menu.hidden = true; }, 150);
  }

  focusItem(index) {
    if (index < 0) index = this.items.length - 1;
    if (index >= this.items.length) index = 0;
    this.focusedIndex = index;
    this.items[index].focus();
  }

  handleTriggerKey(e) {
    switch (e.key) {
      case 'ArrowDown': case 'Enter': case ' ':
        e.preventDefault(); this.open(); this.focusItem(0); break;
      case 'ArrowUp':
        e.preventDefault(); this.open(); this.focusItem(this.items.length - 1); break;
    }
  }

  handleMenuKey(e) {
    switch (e.key) {
      case 'ArrowDown': e.preventDefault(); this.focusItem(this.focusedIndex + 1); break;
      case 'ArrowUp': e.preventDefault(); this.focusItem(this.focusedIndex - 1); break;
      case 'Home': e.preventDefault(); this.focusItem(0); break;
      case 'End': e.preventDefault(); this.focusItem(this.items.length - 1); break;
      case 'Enter': case ' ':
        e.preventDefault(); this.items[this.focusedIndex]?.click(); this.close(); break;
      case 'Escape': case 'Tab':
        e.preventDefault(); this.close(); break;
      default:
        // Type-ahead
        if (e.key.length === 1) {
          const char = e.key.toLowerCase();
          const match = this.items.find((item, i) => i > this.focusedIndex &&
            item.textContent.trim().toLowerCase().startsWith(char)
          ) || this.items.find(item => item.textContent.trim().toLowerCase().startsWith(char));
          if (match) this.focusItem(this.items.indexOf(match));
        }
    }
  }
}
```

### 9.13 Web Components

```typescript
class UiDropdownMenu extends HTMLElement {
  connectedCallback() {
    this.attachShadow({ mode: 'open' });
    this.render();
    this.trigger = this.shadowRoot!.querySelector('.trigger')!;
    this.menu = this.shadowRoot!.querySelector('[role="menu"]')!;
    this.trigger.addEventListener('click', () => this.toggle());
    this.trigger.addEventListener('keydown', (e: any) => this.handleTriggerKey(e));
    this.menu.addEventListener('keydown', (e: any) => this.handleMenuKey(e));
    document.addEventListener('click', (e) => { if (!this.contains(e.target as Node)) this.close(); });
  }

  get items() { return [...this.menu.querySelectorAll('[role="menuitem"]')] as HTMLElement[]; }
  get isOpen() { return !this.menu.hidden; }

  toggle() { this.isOpen ? this.close() : this.open(); }

  open() {
    this.menu.hidden = false;
    this.trigger.setAttribute('aria-expanded', 'true');
    this.items[0]?.focus();
  }

  close() {
    this.menu.hidden = true;
    this.trigger.setAttribute('aria-expanded', 'false');
    this.trigger.focus();
  }

  handleTriggerKey(e: KeyboardEvent) {
    if (['ArrowDown', 'Enter', ' '].includes(e.key)) { e.preventDefault(); this.open(); }
  }

  handleMenuKey(e: KeyboardEvent) {
    const items = this.items;
    const focused = this.shadowRoot!.activeElement as HTMLElement;
    const index = items.indexOf(focused);
    switch (e.key) {
      case 'ArrowDown': e.preventDefault(); items[(index + 1) % items.length]?.focus(); break;
      case 'ArrowUp': e.preventDefault(); items[(index - 1 + items.length) % items.length]?.focus(); break;
      case 'Escape': this.close(); break;
      case 'Enter': case ' ': e.preventDefault(); focused?.click(); this.close(); break;
    }
  }

  render() {
    const itemsData = JSON.parse(this.getAttribute('items') || '[]');
```

## 10\. Accessibility
**`role="menu"`** **+** **`role="menuitem"`** is the correct ARIA pattern here because these are _actions/commands_, not navigation links. This is the one place where `role="menu"` is right (unlike nav, where it's wrong).

**Trigger:** `aria-haspopup="true"` (or `"menu"`), `aria-expanded` tracking open/closed state, `aria-controls` pointing at the menu ID.

**Keyboard contract (the full WAI-ARIA menu pattern):**

| Key | Action |
| ---| --- |
| Enter / Space / ArrowDown (on trigger) | Open menu, focus first item |
| ArrowUp (on trigger) | Open menu, focus last item |
| ArrowDown (in menu) | Next item (wraps to first) |
| ArrowUp (in menu) | Previous item (wraps to last) |
| Home | First item |
| End | Last item |
| Enter / Space (on item) | Activate item, close menu |
| Escape | Close menu, return focus to trigger |
| Tab | Close menu, move focus naturally |
| Type-ahead | Jump to item starting with typed character |
| ArrowRight (on submenu trigger) | Open submenu |
| ArrowLeft (in submenu) | Close submenu, return to parent |

**Focus management:**
*   On open: focus moves to the first enabled item (or the last if opened via ArrowUp).
*   On close (Escape, selection, outside click): focus returns to the trigger. This is the #1 bug in custom menus.
*   Disabled items are skipped by arrow navigation but remain in the DOM for discoverability. They carry `aria-disabled="true"`.

**Separators** use `role="separator"` — they're non-focusable and skipped by keyboard.

**Destructive items** should have a distinct visual (red) AND a confirmation before the action fires. Color alone is not sufficient for signaling danger.

**Touch targets ≥ 44px** per item. Desktop menus can be visually compact (32px) but must still be ≥44px on touch devices.

**Contrast:** item text vs. menu background ≥ 4.5:1. Hover/focus highlight must not reduce contrast below threshold.

**Submenus** announce their trigger as expandable (`aria-haspopup="menu"` + `aria-expanded` on the parent item).

## 11\. Innovative / Emerging Ideas
*   **Command menu hybrid:** dropdown that includes a search filter (command palette lite)
*   **AI-suggested actions:** contextual actions surfaced by AI based on content
*   **Animated entrance:** menu items stagger in (honor reduced-motion)
*   **Nested confirmation:** destructive items expand inline to confirm instead of a separate dialog

* * *
## 12\. Conversion / UX Killers
*   **No keyboard support:** mouse-only menus are an accessibility failure
*   **Focus not returning to trigger on close:** user loses their place
*   **Tiny hit targets:** menu items under 44px on touch devices
*   **Too many items:** 15+ items in a flat list. Group, paginate, or rethink.
*   **Hidden behind a kebab with no affordance:** users don't discover the actions exist
*   **Destructive action without confirmation:** one misclick deletes forever

* * *
## 13\. Advanced Patterns
**Compound menus:** checkbox items for toggleable options ("Show grid", "Show labels") and radio items for exclusive options ("Sort by: Name / Date / Size").

**Inline confirmation:** instead of a confirm dialog, the "Delete" item transforms into "Confirm delete?" + "Cancel" within the menu.

**Floating UI positioning:** use Floating UI / Popper to handle viewport edges, flipping, and shifting.

* * *
## 14\. Performance & Bundle Cost
*   **Render menu on open, not on mount.** A page with 50 rows each having a menu = 50 hidden menus in the DOM. Use a portal and render only the active one.
*   **Event delegation:** one menu instance repositioned per trigger, not one per row.
*   **Exit animation:** if using an exit animation, clean up the DOM after it completes (don't leave invisible menus in the tree).

* * *
## 15\. Security
*   **CSRF on destructive actions.** A menu item that fires a DELETE request needs CSRF protection. The menu click shouldn't be the only gate.
*   **Authorization check per item.** Don't show "Delete" to users who can't delete. Server-side permission check before rendering the item.

* * *
## 16\. Senior-Level Checklist
*   `role="menu"` + `role="menuitem"` structure
*   `aria-haspopup`, `aria-expanded` on trigger
*   Full keyboard contract (arrows, enter, escape, type-ahead)
*   Focus moves into menu on open, returns to trigger on close
*   Disabled items are `aria-disabled` and skipped by arrows
*   Destructive items visually distinct + have confirmation
*   Items ≥44px on touch
*   Menu rendered in portal, positioned with Floating UI
*   Exit: focus never stranded
