# Stepper/Wizard

# The Stepper/Wizard: A Senior Engineer's Complete Breakdown
The component that breaks complex processes into digestible steps. Here's everything from first principles to production code.

This doc follows the Private ([https://app.clickup.com/8495850/docs/838qa-81211/838qa-200531](https://app.clickup.com/8495850/docs/838qa-81211/838qa-200531)) and its visual styles are drawn from the Private ([https://app.clickup.com/8495850/docs/838qa-87871/838qa-200551](https://app.clickup.com/8495850/docs/838qa-87871/838qa-200551)).

* * *
## 1\. What a Stepper Actually Is
A **stepper** (wizard, multi-step indicator, progress stepper) is a visual representation of a multi-step process showing the user where they are, what they've completed, and what's ahead. It's both a progress indicator and a navigation aid.

**Stepper (this doc):** numbered/labeled steps with completion states. Shows the full journey.
**Progress bar:** shows completion percentage without discrete steps.
**Tabs:** switch between views that are peers, not sequential.
**Breadcrumb:** shows hierarchy (where you are in a tree), not sequence.

* * *
## 2\. Why It Matters
**Completion rates.** Breaking a 12-field form into 3 steps of 4 fields dramatically improves completion. Users see "step 2 of 3" and feel progress; they see a single 12-field wall and leave.
**Cognitive load reduction.** Each step focuses attention on one task. The stepper provides the "you are here" context that prevents overwhelm.
**Drop-off diagnosis.** Analytics on which step users abandon tells you exactly where the friction is.

* * *
## 3\. Anatomy
**Step indicator:** a numbered circle, icon, or dot marking each step.
**Label:** text describing the step ("Shipping", "Payment", "Review").
**Connector:** a line between indicators showing sequence and progress.
**Active indicator:** visually distinct current step (filled, highlighted).
**Completed indicator:** shows checkmark or filled state for finished steps.
**Upcoming indicator:** muted/outlined for steps not yet reached.
**Optional description:** subtitle under the label for additional context.

* * *
## 4\. Sizes / Scale

| Token | Indicator | Connector | Label | Use |
| ---| ---| ---| ---| --- |
| S | 24px | 2px H | 12px | Compact, mobile |
| M | 32px | 2px H | 14px | Default |
| L | 40px | 3px H | 16px | Prominent, desktop |

Horizontal steppers need enough width to display labels. When labels don't fit, collapse to icons-only or switch to vertical.

* * *
## 5\. States
**Completed:** checkmark icon, filled/colored indicator, solid connector to next.
**Active/Current:** highlighted indicator (brand color), possibly pulsing or larger.
**Upcoming:** muted/outlined indicator, dashed or light connector.
**Error:** a specific step failed (red indicator, error icon). Shows where the problem is.
**Disabled/Locked:** a step can't be accessed yet (sequential flow, dependency not met).
**Optional:** a step that can be skipped (shown with "Optional" label).
**Clickable vs Non-clickable:** can completed steps be clicked to go back? Design choice with navigation implications.

* * *
## 6\. Types / Variants
**Horizontal:** steps laid out left-to-right. Standard for desktop, 3-5 steps max.
**Vertical:** steps stacked top-to-bottom. Better for mobile and long descriptions. Content can appear inline beside each step.
**Dot/Minimal:** just dots connected by lines, no numbers or icons. Space-efficient.
**With content:** each step reveals its content below/beside the stepper (accordion-like).
**Non-linear:** steps can be completed in any order (dashboard setup). Less common.
**Mobile alternative:** when horizontal doesn't fit, show "Step 2 of 4" text + progress bar.

* * *
## 7\. When to Use (and When Not To)
**Use a stepper when:**
*   A process has 3-7 discrete sequential steps
*   Users benefit from knowing progress and what's ahead
*   Each step is complex enough to warrant its own view
*   You want to validate step-by-step before final submission

**Use something else when:**
*   Only 2 steps → just show a "Next" button with a simple indicator
*   More than 7 steps → group into phases or simplify the process
*   Steps are independent (not sequential) → Tabs or dashboard
*   The process is very short → single form, no stepper needed

* * *
## 8\. Across Design Systems
**Material:** `Stepper` with horizontal/vertical, linear/non-linear, alternativeLabel. Full-featured.
**Apple HIG:** no explicit stepper component. Built custom with page indicators or "1 of 4" text.
**Fluent:** no dedicated stepper; teams build custom using `Steps` patterns.
**Ant Design:** `<Steps>` with direction, status, current, and clickable navigation.
**Chakra:** `<Stepper>` with `<Step>`, `<StepIndicator>`, `<StepSeparator>` composition.
**shadcn:** no built-in; community recipes compose from primitives.

### 9.3 React + TypeScript

```typescript
type StepStatus = "completed" | "active" | "upcoming" | "error";

interface Step { label: string; description?: string; status: StepStatus; optional?: boolean; }

interface StepperProps {
  steps: Step[];
  orientation?: "horizontal" | "vertical";
  onStepClick?: (index: number) => void;
}

export function Stepper({ steps, orientation = "horizontal", onStepClick }: StepperProps) {
  return (
    <nav aria-label="Progress"><ol className={`stepper stepper--${orientation}`}>
        {steps.map((step, i) => (
          <li key={i} className={`stepper__step stepper__step--${step.status}`}
              aria-current={step.status === "active" ? "step" : undefined}>
            <span className="stepper__indicator" aria-hidden="true">
              {step.status === "completed" ? "✓" : step.status === "error" ? "!" : i + 1}
            </span>
            <span className="stepper__label">
              {step.label}
              {step.optional && <span className="stepper__optional">Optional</span>}
            </span>
            {step.description && <span className="stepper__desc">{step.description}</span>}
          </li>
        ))}
      </ol>
    </nav>
  );
}
```

```typescript
"use client";
import { usePathname } from "next/navigation";
import { Stepper } from "./stepper";

export function CheckoutStepper({ steps }: { steps: Array<{ label: string; path: string }> }) {
  const pathname = usePathname();
  const currentIndex = steps.findIndex(s => pathname.startsWith(s.path));

  const stepData = steps.map((s, i) => ({
    label: s.label,
    status: i < currentIndex ? "completed" : i === currentIndex ? "active" : "upcoming" as const,
  }));

  return <Stepper steps={stepData} />;
}
```

```typescript
// components/ui/stepper.tsx
import { cn } from "@/lib/utils";
import { Check, AlertCircle } from "lucide-react";

type StepStatus = "completed" | "active" | "upcoming" | "error";
interface Step { label: string; description?: string; status: StepStatus; optional?: boolean; }

interface StepperProps {
  steps: Step[];
  orientation?: "horizontal" | "vertical";
  className?: string;
}

export function Stepper({ steps, orientation = "horizontal", className }: StepperProps) {
  return (
    <nav aria-label="Progress" className={className}>
      <ol className={cn("flex", orientation === "vertical" ? "flex-col gap-0" : "items-center gap-0")}>
        {steps.map((step, i) => (
          <li key={i} className={cn("flex-1 relative", orientation === "vertical" && "pb-8 last:pb-0")}
              aria-current={step.status === "active" ? "step" : undefined}>
            <div className={cn("flex items-center", orientation === "vertical" ? "gap-3" : "flex-col gap-2")}>
              {/* Indicator */}
              <div className={cn(
                "w-8 h-8 rounded-full flex items-center justify-center text-sm font-semibold z-10 shrink-0",
                step.status === "completed" && "bg-primary text-primary-foreground",
                step.status === "active" && "bg-accent text-accent-foreground ring-4 ring-accent/20",
                step.status === "upcoming" && "border-2 border-muted text-muted-foreground",
                step.status === "error" && "bg-destructive text-destructive-foreground"
              )} aria-hidden="true">
                {step.status === "completed" && <Check className="w-4 h-4" />}
                {step.status === "error" && <AlertCircle className="w-4 h-4" />}
                {(step.status === "active" || step.status === "upcoming") && i + 1}
              </div>
              {/* Label */}
              <div className={cn("text-center", orientation === "vertical" && "text-left")}>
                <span className={cn("text-xs font-medium", step.status === "active" && "text-foreground", step.status === "upcoming" && "text-muted-foreground")}>
                  {step.label}
                </span>
                {step.description && <span className="block text-xs text-muted-foreground">{step.description}</span>}
                {step.optional && <span className="block text-xs text-muted-foreground italic">Optional</span>}
              </div>
            </div>
            {/* Connector */}
            {i < steps.length - 1 && (
              <div className={cn(
                "absolute",
                orientation === "horizontal" ? "top-4 left-[calc(50%+20px)] right-[calc(-50%+20px)] h-0.5" : "left-4 top-10 bottom-2 w-0.5",
                step.status === "completed" ? "bg-primary" : "bg-muted"
              )} aria-hidden="true" />
            )}
          </li>
        ))}
      </ol>
    </nav>
  );
}
```

### 9.13 SwiftUI

```swift
import SwiftUI

struct StepperView: View {
    let steps: [StepItem]
    var orientation: Axis = .horizontal

    struct StepItem: Identifiable {
        let id = UUID()
        let label: String
        let status: Status
        enum Status { case completed, active, upcoming, error }
    }

    var body: some View {
        if orientation == .horizontal {
            HStack(spacing: 0) { content }
        } else {
            VStack(alignment: .leading, spacing: 0) { content }
        }
    }

    @ViewBuilder
    var content: some View {
        ForEach(Array(steps.enumerated()), id: \.element.id) { index, step in
            HStack(spacing: 8) {
                // Indicator
                ZStack {
                    Circle()
                        .fill(step.status.color)
                        .frame(width: 32, height: 32)
                    switch step.status {
                    case .completed: Image(systemName: "checkmark").font(.system(size: 12, weight: .bold)).foregroundColor(.white)
                    case .error: Image(systemName: "exclamationmark").font(.system(size: 12, weight: .bold)).foregroundColor(.white)
                    default: Text("\(index + 1)").font(.system(size: 14, weight: .semibold)).foregroundColor(step.status == .active ? .black : .gray)
                    }
                }
                Text(step.label)
                    .font(.caption)
                    .fontWeight(step.status == .active ? .semibold : .regular)
                    .foregroundColor(step.status == .upcoming ? .gray : .primary)

                // Connector
                if index < steps.count - 1 {
                    Rectangle()
                        .fill(step.status == .completed ? Color.purple : Color.gray.opacity(0.3))
                        .frame(height: 2)
                        .frame(maxWidth: .infinity)
                }
            }
            .accessibilityElement(children: .combine)
            .accessibilityLabel("\(step.label), \(step.status.accessibilityLabel)")
            .accessibilityAddTraits(step.status == .active ? .isSelected : [])
        }
    }
}

extension StepperView.StepItem.Status {
    var color: Color {
        switch self {
        case .completed: return .purple
        case .active: return Color(red: 0.86, green: 0.64, blue: 0.14) // Goldenrod
        case .upcoming: return Color.gray.opacity(0.2)
        case .error: return .red
        }
    }
    var accessibilityLabel: String {
        switch self {
        case .completed: return "completed"
        case .active: return "current step"
        case .upcoming: return "upcoming"
        case .error: return "error"
        }
    }
}
```

```kotlin
                            StepStatus.Active -> Color(0xFFDCA424)
                            StepStatus.Upcoming -> Color(0xFF333333)
                            StepStatus.Error -> Color(0xFFB42318)
                        })
                        .semantics {
                            contentDescription = "${step.label}, ${step.status.name.lowercase()}"
                            if (step.status == StepStatus.Active) selected = true
                        }
                ) {
                    when (step.status) {
                        StepStatus.Completed -> Icon(Icons.Default.Check, null, tint = Color.White, modifier = Modifier.size(16.dp))
                        StepStatus.Error -> Text("!", color = Color.White, style = MaterialTheme.typography.labelMedium)
                        else -> Text("${index + 1}", color = if (step.status == StepStatus.Active) Color.Black else Color.Gray, style = MaterialTheme.typography.labelMedium)
                    }
                }
                Spacer(modifier = Modifier.height(4.dp))
                Text(step.label, style = MaterialTheme.typography.labelSmall,
                     color = if (step.status == StepStatus.Upcoming) Color.Gray else MaterialTheme.colorScheme.onSurface)
            }
            // Connector
            if (index < steps.size - 1) {
                Box(modifier = Modifier
                    .weight(0.5f)
                    .height(2.dp)
                    .background(if (step.status == StepStatus.Completed) Color(0xFF5F2C82) else Color(0xFF444444))
                )
            }
        }
    }
}
```

```dart
import 'package:flutter/material.dart';

enum StepStatus { completed, active, upcoming, error }

class StepItem {
  final String label;
  final StepStatus status;
  final String? description;
  const StepItem({required this.label, required this.status, this.description});
}

class StepperWidget extends StatelessWidget {
  final List<StepItem> steps;
  final Axis orientation;

  const StepperWidget({super.key, required this.steps, this.orientation = Axis.horizontal});

  @override
  Widget build(BuildContext context) {
    // Flutter's built-in Stepper widget:
    return Stepper(
      currentStep: steps.indexWhere((s) => s.status == StepStatus.active),
      type: orientation == Axis.horizontal ? StepperType.horizontal : StepperType.vertical,
      controlsBuilder: (context, details) => const SizedBox.shrink(), // Hide default buttons
      steps: steps.asMap().entries.map((entry) {
        final i = entry.key;
        final step = entry.value;
        return Step(
          title: Text(step.label),
          subtitle: step.description != null ? Text(step.description!) : null,
          content: const SizedBox.shrink(),
          isActive: step.status == StepStatus.active,
          state: _mapState(step.status),
        );
      }).toList(),
    );
  }

  StepState _mapState(StepStatus status) {
    switch (status) {
      case StepStatus.completed: return StepState.complete;
      case StepStatus.active: return StepState.editing;
      case StepStatus.error: return StepState.error;
      case StepStatus.upcoming: return StepState.indexed;
    }
  }
}
```

## 10\. Accessibility
**Semantic structure:** wrap the stepper in `<nav aria-label="Progress">` with an `<ol>` (ordered list, because sequence matters). Each step is an `<li>`. This gives screen-reader users "navigation, Progress, list, 3 items" immediately.

**`aria-current="step"`** on the active step. This is the semantic signal for "you are here in the process." Only one step carries it at a time.

**Step indicators are** **`aria-hidden="true"`****.** The checkmark, number, or error icon is decorative — the label text already names the step. Don't make AT announce "checkmark, Shipping, 2, Payment."

**Step status in the accessible name.** For clickable steppers where completed steps are revisitable, each step's accessible name should include its status: "Shipping, completed" / "Payment, current step" / "Review, upcoming." Use `aria-label` or visually-hidden text.

**Color is never the only status signal.** Completed = checkmark icon + filled color. Error = error icon + red. Active = distinct styling + `aria-current`. Users who can't see color still know the status via icon shape and text.

**Clickable completed steps** (when users can go back) are real `<button>`s or `<a>`s with accessible names. Upcoming/locked steps are non-interactive and carry `aria-disabled="true"` if shown.

**Focus management on step change.** When advancing to a new step, move focus to the new step's first input or heading so keyboard users land in the right place. Don't leave focus on the "Next" button that's now contextually wrong.

**Announce step changes.** An `aria-live="polite"` region (or focus moving to a heading) should announce "Step 2 of 3: Payment" when the step changes, so screen-reader users know progress moved.

**Mobile alternative:** when the stepper collapses to "Step 2 of 3" text, that text must be live-updated and announced. The full visual stepper is a progressive enhancement.

## 11\. Innovative / Emerging Ideas
*   **Animated connectors:** fill animation as a step completes
*   **Stepper with estimated time:** "Step 2 of 3 (≈2 min remaining)"
*   **Branching steppers:** step 3 varies based on step 2's answer
*   **AI-assisted skip:** auto-fill steps from prior data, skip to review

* * *
## 12\. Conversion / UX Killers
*   **No back navigation:** users can't correct step 1 from step 3. Forces restart.
*   **Data loss on back:** going back clears step 2's data. Devastating.
*   **Too many steps:** 8+ steps signals bureaucracy. Consolidate or hide optional steps.
*   **No progress persistence:** refresh loses all progress. Save per-step to server/localStorage.
*   **Hidden step count:** users don't know how long the process is. Show total.

* * *
## 13\. Advanced Patterns
**Step validation before advance:** disable "Next" until current step is valid. Show inline errors.

**Persist per step:** save each completed step to the server immediately. User can leave and return.

**Responsive collapse:** horizontal on desktop, vertical on tablet, "Step X of Y" + progress bar on mobile.

* * *
## 14\. Performance & Bundle Cost
Lightweight component. The only performance concern is **step content lazy loading** — don't mount all step content at once if steps contain heavy forms or images. Render only the active step's content.

* * *
## 15\. Security
*   **Don't trust step order client-side.** Users can skip steps via URL manipulation or devtools. Validate the entire flow server-side before final submission.
*   **Prevent step 3 access without step 1-2 completion** on the server, not just via UI disable.

* * *
## 16\. Senior-Level Checklist
*   `<nav>` + `<ol>` semantic structure
*   `aria-current="step"` on active step
*   Step status conveyed by more than color (icon + text)
*   Back navigation preserves data
*   Progress persisted (server or localStorage)
*   Step validation before advance
*   Responsive: collapses gracefully on mobile
*   Server validates full flow, not just UI step order
